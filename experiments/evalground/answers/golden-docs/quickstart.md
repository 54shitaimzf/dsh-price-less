### 步骤 1：跑一遍测试，确认基线

运行 `npm test`。预期看到领域与契约测试全部执行完毕，退出码 0 表示环境健康；
若存在失败用例，先对照 `tests/` 定位，不要跳过。

常见问题：若在 Windows 下遇到子进程被拒（EPERM），在命令后追加
`--test-isolation=none` 参数即可让测试在进程内运行。

### 步骤 2：运行自检确认场地完整

运行 `npm run check`。预期输出 `self-check OK: fixture ground healthy`，
它核对了数据文件、样例包与产物 tarball 是否齐备。

常见问题：自检报缺文件时，先确认是否从模板完整拷贝；缺少 tarball 时运行
`node scripts/make-tgz.mjs` 重新生成（位于 evalground 目录）。

### 步骤 3：启动审计服务

运行 `npm run start`。预期启动后监听 http://127.0.0.1:8787（本机地址），
按下 Ctrl+C 可停止。

常见问题：端口被占用时会看到 EADDRINUSE，换端口或先结束旧进程即可。

### 步骤 4：触发一次审计

浏览器打开 http://127.0.0.1:8787/，报告面板会自动调用 `/api/audit` 对
样例插件包执行完整审计并渲染摘要卡与发现表；也可以直接访问
http://127.0.0.1:8787/api/audit 看原始 JSON。

常见问题：面板显示"加载中"不动时，检查浏览器控制台是否拦截了同源请求；
所有接口都在本机服务上，无需网络。

### 步骤 5：查看审计结果

面板中按严重度（错误/警告/提示）分卡片展示，表格列出每条发现的
规则编号、级别、说明与文件。若发现表为空或异常，回到步骤 1 先确认
自检与测试都通过，再对照 `docs/rules.md` 确认规则口径。
