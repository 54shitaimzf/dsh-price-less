### 2.2 决策点记录

1. **onUsage 遏制 = 兜底，不是给回调开免责**：P10/P11/P18 的 onUsage 实现仍应写纯函数
   （fold 入账），不得依赖“抛错被吞”来掩盖 bug；本单只保证度量侧 bug 不会打断机制主路径。
2. **catch 后不重抛**：即使 `hooks.logger` 未提供也只遏制（与 `events.ts` 监听器异常处理
   同构）。诊断 warn 文案固定为
   `context-economy: llm usage receipt callback failed (contained)`。
3. **`yield chunk` 保持在 try 之外**：遏制范围只限 `onUsage` 回调本身；usage 块与全部
   流块的透传不受影响。
4. **新测试独立成文件**：`tests/llm-purpose.spec.ts` 已 168 行，接近 P5 预算 180；本单
   不追加进该文件，新文件预算 ≤80 行。
5. **docs/10 状态行按已施工事实写**：H10（P3 `storage.ts`）、H13（P4 `skills.ts`）与
   H12（P5 `llm.ts`）都是已施工；不新增 H2/H3/H4/H5/H6/H9 等未施工项。
6. **不改 D6/assert 规则**：本单未新增 llm 概念越界风险；D6 与零位快照保持不变。

## 3. 产出

### 3.1 `src/platform/llm.ts`（改，净增 ≤20 行）

```ts
export async function* streamCeLlm(
  ctx: Pick<Context, 'llm'>,
  options: CeGenerateOptions,
  hooks?: CeLlmStreamHooks,
): AsyncGenerator<StreamChunk, void, unknown> {
  // ...服务缺失分支不变...
  let usageSeen = false
  for await (const chunk of service.stream(toHarnessGenerateOptions(options))) {
    if (chunk.type === 'usage' && !usageSeen) {
      usageSeen = true
      try {
        hooks?.onUsage?.({
          purpose: options.purpose,
          provider: options.provider,
          model: options.model,
          usage: toCeLlmUsage(chunk.usage),
        })
      } catch (e) {
        hooks?.logger?.warn(
          'context-economy: llm usage receipt callback failed (contained)',
          e instanceof Error ? e.message : String(e),
        )
      }
    }
    yield chunk
  }
}
```

同时更新 JSDoc：
- `CeLlmStreamHooks.onUsage`：`usage 块首次到达时单次回调；无 usage 不回调。回调抛错只 warn 不外溢（不中断流）。`
- `streamCeLlm` 注释：`usage 回执：首个 usage 块触发 hooks.onUsage 一次；onUsage 抛错只 warn 不外溢；流块全部原样透传。`

### 3.2 `tests/llm-stream-robustness.spec.ts`（新，≤80 行；全部 fake）

手写 fake async generator；零 cordis 运行时 import。两个用例：

1. **onUsage 抛错遏制**：fake service 依次 yield `text-delta`、`usage`、`finish`；
   `onUsage` 直接 `throw new Error('ledger boom')`；`logger.warn` 收集。断言：
   - 迭代 `streamCeLlm` 不抛；收到 3 个流块且 `toStrictEqual` 原块；
   - `warns` 恰 1 条且含 `llm usage receipt callback failed (contained)`；
   - usage 块照常透传（没有被 catch 吞掉）。
2. **消费者提前 break：usage 未到不回执，且内层流被关闭**：fake service 为
   `try { yield text; yield usage } finally { closed = true }`；用手动迭代器
   `const it = streamCeLlm(...)[Symbol.asyncIterator]()` 取第一个块后 `await it.return()`。
   断言：`receipts` 长度为 0；`closed === true`（内层 iterator 被 return 关闭）；
   首个块值等于 text。
