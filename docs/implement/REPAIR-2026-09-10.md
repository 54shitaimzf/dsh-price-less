（`packages/core/session/src/surface.ts`）要求**恰好** 3 个键且名为 `op`/`startSeq`/`endSeq`，否则
`throw new Error('session event "…" carries an invalid replace surfaceOp')`。因 cast 绕过编译器：
**typecheck 全绿，运行期第一次改史即炸**——波及全部压缩 checkpoint 提交、P16 对话剪切 run 冲刷、T0/T0-R 超越剪除。
这是本次审查唯一"编译器失守"的位置。

改动清单：
1. **端点名单一常量**：模块级抽 `const REPLACE_OP_KEYS = { start: 'start', end: 'end' } as const`
   （HC1 选 B 时只改这两行），`:211` 的 cast 类型与 `:223`/`:256` 的构造共用；
2. **补编译期双向锚**（学 `platform/star-bridge.ts:51-57`）：
   ```ts
   export type ReplaceOpAnchor = AssertAssignable<
     { op: 'replace'; start: SessionSeq; end: SessionSeq },   // 本仓形状
     Extract<SurfaceOp, { op: 'replace' }>                     // harness 权威形状（真源）
   >
   ```
   **该锚在 A 基线成立、在 B 基线必须红**——这正是它的价值（漂移即 typecheck 红）。HC1 选 B 时同改本地形状，锚回落绿；
3. **同法清扫其余无锚 cast**：`ignorable-channel.ts:87`（append 适配器）、`history.ts:208`、
   各域里的 `session as unknown as { snapshotEvents… }`——能加锚的加锚，不能的在 §6.2 legacy 登记里写明理由。

**验收**：A 基线 `npm run gate` 全绿 + `tests/history-real-session.spec.ts` 绿；B 基线该用例绿、
`vitest` 仅剩 HC3 的三条（`ce-logger` ×2 + `harness-session`，且按 8.3 处置）。
