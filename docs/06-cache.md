# 06 · 缓存纪律（缓存复用正典）

> 域定义：**缓存体制命题 + 断裂成本公式 + 字节稳定铁律**——一切上下文机制（剪切时机、
> 版本 bump、压缩产物、稳定前缀）的经济学地基。被 [03](03-shear.md)（剪切时机）、
> [04](04-compactor.md)（产物稳定）、[09](09-state.md)（版本协议）共同引用。
> 状态：设计 · 未实现（观测字段见 [07](07-metrics.md)）。

## 0. 它解决什么问题（人话版）

请求开头那一大段如果每次一模一样，服务端直接复用已算好的部分——白拿的性能，而且是我们
这套件**最大的一笔收入**：命中缓存的部分按折扣计价，机制省下的每一 token 若把前缀弄断，
就全数还回去还要倒贴。痛点就在"一个字节都不能变"非常难守：改个摘要、调个词表、原地修个
历史段，前缀就断了，后面全部重算。

这篇定三件事：**我们的缓存体制是什么**（决定了哪些策略对我们最优、哪些对别人最优的策略
对我们有害）；**动前缀的价格公式**（任何想动历史字节的设计，先过这条公式）；**守前缀的
铁律**（同输入同输出、稳定在前、变更走版本）。

## 1. 缓存体制命题（体制决定策略）

**缓存的计费结构、命中率与 TTL，决定该体制下的最优上下文策略。**

| | 本套件目标体制（DeepSeek 直连实测） | 高压截断体制（部分厂商 harness 的处境） |
|---|---|---|
| 读折扣 | 命中部分大幅折扣（实测命中率可达九成量级） | 命中率低 / TTL 短（分钟级失效） |
| 写溢价 | 无写加价 | 写入缓存加价（+25%~2× 量级） |
| 服务端缓存操作 | **无**（不能主动管理缓存条目） | 有（缓存编辑类操作） |
| 最优策略 | **字节稳定、追加式、缝贴尾、语义调度版本 bump**——保前缀是最大收入 | 硬截断 / 整窗替换反而是理性选择（反正留不住缓存） |

三条推论：

1. **不照搬别人的截断**：低命中率体制下的激进截断策略，搬到我们体制 = 放着九成命中不要，
   白付重算钱。一切"别人这么干"的机制先过本表再考虑。
2. **换模型 = 换体制 = 整批重跑**：计费结构随 provider 变，全部成本结论作废——这是
   "换评测模型必须整批重跑并标注"硬规则的深层根据（AGENTS.md）。
3. **缓存命中率是一等公民指标**：`cacheReadTokens` 读标准 usage 字段
   （`prompt_tokens_details.cached_tokens`，兜底各家别名），漏读 = 成本按无缓存高估。

## 2. 断裂成本公式（动前缀的价格）

> **断裂成本 = 变更点之后全部体积 × 全价**（一次性重算）。

- **正收益变更**只有两类：变更点贴近尾部（尾巴极短），或完整版从未入账（写时整形）。
  **中段独立变更被公式直接否定**——这是剪切层时机四档（[03 §1](03-shear.md)）、
  对话 run 冲刷贴动作（[03 §3](03-shear.md)）的公共根据。
- **版本 bump 是受控断裂**：稳定前缀的版本升级（项目帧修订、档案追加）承认一次性全价
  重算，换取此后长周期的命中——bump 时机按**语义调度**（task 边界、星标时刻、技能装卸），
  绝不高频。
- 判别/断面调用复用同一前缀 + 短尾（模板在前、实例在后），调用越多边际越便宜——
  **卷宗积累不只是精度设计，更是让搭车近乎免费的缓存基底**。

## 3. 字节稳定三铁律

1. **同输入 → 同输出**：相同组装结果必须逐字节一致（稳定前缀、优化产物、档案、摘要、
   热尾装配）；
2. **稳定在前，动态在后**：system、tools、稳定前缀、档案堆 = 前缀；实例参数、当前消息、
   用户指令 = 尾区；
3. **变更走版本**：内容变化 → 版本 +1 → 一次受控重建；杜绝原地改写历史段
   （配合 [04 §1](04-compactor.md) 改史唯一通道）。

## 4. 稳定前缀版本纪律

- 稳定前缀 = **技能目录 + 项目最终目标**（[02 §2](02-discriminator.md) 输入栈①）；
  版本事件只有三种：技能装卸（目录变更，机械触发）、项目帧修订（用户确认后 bump）、
  压缩域档案追加（[04 §6](04-compactor.md)）。
- 每次 bump 记 `prefixRebuildCount` 与重价体积（`prefixRebuildTokens`）；
  bump 理由枚举 `{shear | compaction | note | skill | frame}` 入账。
- 档案堆只追加不可改写；越界按 15K 硬帽整条截断最老条目（[04 §6](04-compactor.md)）——
  截断本身也是 bump（版本 +1），按硬帽触发不按时间触发。

## 5. 深度冻结原则

历史深处的文件读内容**不做无据删除**：要么结论已在场（语义在场），要么盘上可取回
（盘上在场，写即新真相、盘是权威）；删缓存收益是折扣价小钱，丢依据的代价是全价重发现。
（与剪除落位律 [03 §4](03-shear.md) 同一根基：上下文是模型唯一记忆。）

## 6. 位置纪律与辅助调用对齐

- 用户指令恒为最后一条（最高近因）；稳定前缀与档案堆前置于头区；
- 尾部允许变化（新消息/实例参数），变化幅度 = 每轮重算成本，也是断裂公式的日常形态；
- 一切辅助调用（判别/断面/压缩）= **上一次路由请求的真前缀 + 新短尾**——
  复用而非失效缓存。

## 7. 冷热分离度量与验收

- 命中率按冷（清缓存首跑）/ 热（连续跑）两列报告；`cacheHitInputTokens` 差分；
- 断裂事件（版本 bump、硬帽截断、保险丝）全部计数入账。

- [ ] 同版本稳定前缀 / 档案 / 优化产物逐字节一致（哈希 CI）；
- [ ] 辅助调用前缀 = 上一次请求前缀（回放断言）；
- [ ] 断裂成本可回放重算（公式对账：bump 后下一请求的缓存 miss ≈ 变更点后体积）；
- [ ] 缓存观测字段不缺位（usage 标准路径 + 别名兜底）。
