# 03 · 剪切层（第一层防御）

> 域定义：**剪切层管两次边界之间的高频小额上下文微削**——单位是**交换对**（问答对 / 工具对，

## 0. 它解决什么问题（人话版）

历史里最大的体积黑洞不是对话，是**工具结果**：一次 read 几千行、一次 run 满屏日志，进来之后就在每一轮的请求里反复计费——而其中大部分早就没用了（已被后续写超越的旧读、已交付结论的中间过程）。另一类黑洞是**追问链**：你连着问了五个"为什么"，每一问一答都还躺在上下文里，但你的理解早已完成、后面全是动作了。

剪切层就是持续值班的清道夫：**成熟的、不再被引用的内容，在正确的时机整块移除，只在原地留一句结论**。关键不是"敢删"，是**时机**——删早了模型还在用，删在中段缓存全断（后面所有轮全价重算）。所以整层的灵魂是一条经济学公式（§1），和一条不动刀的底线（§4）。

## 1. 时机经济学（设计总原则）

**断裂成本 = 剪点之后全部体积 × 全价**（一次性重算）。

推论：只有两类剪除时机存在正收益——**断裂点贴近尾部**（剪点后尾巴极短），或**完整版从未入账**（写时整形，断裂成本 0）。**中段独立剪除被该公式直接否定**：删一小块、全价重算一大片，成本不降反增。全层所有时机选择（T-entry 优先、T-loop/T-note 贴消费、run 冲刷贴动作、老调用对只许 T-boundary 搭车）都是这条公式的应用。

## 2. 工具剪切器（结构半边）

**架构**：判断耦合出去，执行收拢回来——工具自声明生命周期谓词，janitor 集中持刀
（同构 GC：对象不自我释放，收集器独占回收）。每请求的 tools 数组（模型可见 schema）
**不耦合**——请求缓存稳定性优先。

**生命周期谓词**（`ToolContextLifecycle`，纯 L0 零 LLM）：
`referenceKeys(call)` 身份键（read→path、edit→path、grep→query）· `rederiveCost` 重推导成本档
（trivial/cheap/expensive）· `supersededBy(call, laterEvent)` · `referencedBy(call, laterMessage)`。
未声明工具三级回退：自带策略 → 类别启发式 → 通用体积年龄规则（耦合是已知工具的优化，
不是未知工具的前提）。

**时机四档**（档 = 时机，时机即经济学）：

| 档 | 时机 | 挂点 | 断裂成本 | 准入与动作 |
|---|---|---|---|---|
| T-entry | 写时整形（结果落账**前**） | `tools/post-execute` accept `content` 覆盖（自有工具 `finalizeContent`） | **0**（完整版从未入账） | 严格最优，能做尽做：编译类成功裁几行 / 失败留错因 |
| T-loop | 思考后占位（模型消费完结果） | surfaceOp replace | 一次 + 短尾（剪点 = 刚消费完） | 当次结论极短 + cmd/bash 类；**read 类排除**（喂后续编辑，剪 = 逼重读）；**必须 stub 占位替换而非移除**（保 tool_call 配对防 400） |
| T-note | 注记协商（写时贴注 + 消费后协商剪） | 贴注 = `tools/post-execute` accept 追加；剪除 = surfaceOp replace | 同 T-loop（剪点贴消费） | 见 §2.1 |
| T-boundary | 边界搭车 | task 压缩大 replace | 已付（搭车） | **老调用对唯一合法去处**，绝不中段独立剪 |

> 挂点核验（P1.2 契约闭合）：harness `tools/execute` 的返回结果会经
> `normalizeDispatchResult` 按 `value` 重新渲染 content，wrapper 只改 content 会丢失；
> 因此 T-entry 的落账前整形走 `tools/post-execute` accept `content` 覆盖（自有工具仍走
> 定义侧 `finalizeContent`）。**时机经济学与准入动作不变**，仅修正实现缝。

### 2.1 T-note 注记协商（超长结果的结论提取）

- **动机**：结论不是日志文本的属性，是**日志 × 当前意图**的函数——主模型带全量上下文
  （在修什么、在追什么）消费结果，能立刻抽出"要的那一行"；旁观者（辅助摘要器）只有日志
  没有意图，通用摘要反而可能丢掉正被追猎的报错。故**消费即提取，提取即授权剪切**；
  机械格式剪切保留为基座，注记协商是其增强。**零新增调用**——提取是必要消费调用的附加输出。
- **协议**：准入 = 体积 ≥ 阈值 ∧ 非 read ∧ 非问答（L0）；贴注要求叙述尾部输出结构化标记：
  `CUT-OK:〈一句结论〉` = **调用整对 + 后续思考全部出上下文，仅结论保留**（结论落叙述位 =
  语义在场）；`CUT-HOLD:〈原因〉` = 保留原文至边界搭车。
- **失败语义**：无标记 / 解析失败 / 超时 = **默认保留**——协商不成不动刀，零重试，
  绝不机械代剪（T-loop 有自己独立的类准入，不是 T-note 的失败兜底）。
- **思考剪除前提**：reasoning 回放范围确认后剥离后续 assistant 消息的思考；若回合内回放
  依赖 reasoning，思考剪除推迟至回合闭合，调用对剪除照常（两段分离，账本分开记）。

### 2.2 T0 超越与 T0-R 读件修复

**T0 超越规则**（最高置信，纯机械）：read@t1 被写@t2>t1 超越 → 旧读剪（写即新真相；
路径 + 时序判定，零内容解析）。

**T0-R 读件修复**（读后写特化组装）：**声明表类文件**（同层信息汇总：barrel / 路由表 /
类型与常量表 / schema；判据 = 路径模式 + 写区缩进深度 ≤1，L0）发生读后写时**不整读剪除，
而是修复**——原读剪除（surfaceOp replace，旧事件遮蔽不删除、meta 仍可回放节省额），
写区以盘上最新内容按行回读组装进上下文、保持 read 的 `行号: 文本` 信封格式，
标记 **edited** + `(path, vN, lineRange)` 坐标锚。

三条硬规则：

1. **连发编辑 = 同文件 streak，原位刷新**——streak 内每次编辑对同一读事件再 replace
   （每次从盘重取真相）；streak 被异质操作（其他文件 / 用户轮）打断 → 摘抄冻结在最后版本，
   后续编辑退回普通 T0 全剪；
2. **不准跨事件**——只在相邻同文件操作 streak 内合并，绝不跨异质步做延后修复
   （非相邻 = 剪点入历史中部 = 断裂重演全价，本就是亏损区；约束是划出正收益工作区而非保守）；
3. **不准跨行**——`replace_all` 多 hunk 绝不做 min..max 并集（不跨未写行），逐 hunk 各自成段
   摘抄；段数超限 → 放弃机制退回 T0/保留。

失败设计：对齐歧义 / oldText 不在读窗 / 段数超限 = 不动刀默认保留或退 T0，零重试。
机制收窄 edit-only（write 整文件覆盖不适用——新全文已在 call args）。

### 2.3 落账安全双保险

① assistant 叙述文本 = 结论转写的免费证据（与存活后续文本做实体重叠检查）；
② 重推导兜底（剪错 = 重跑一次，成本有上界——不可重推导的内容一律不许剪）。

**配对纪律**：整对剪（assistant tool_calls + tool/result）或占位替换保结构——
孤儿 tool_call = 400（配对完整性契约，全层共用）。

## 3. 对话剪切器（语义半边）

处理的是**连续追问与连续验证**场景：用户连着问"为什么 X"、"那 Y 呢"，或连着说
"再跑一次"、"确认下没坏"——每轮一问一答都留在上下文里，但价值早已收敛。

- **剪除单位 = 整段 run，不是逐对**。连续追问链是收敛的——后面的追问常常取代前面的，
  逐对留桩会剩一排废桩；整段 run 换一句结论才划算。run = 一段**最大连续**的理解类
  （或验证类）交换串，边界机械可推：从首条理解/验证消息起，到下一条动作类消息或星标为止。
- **触发 = 吸收证明，纯机械**：动作 = 理解已交付的吸收证明（用户开始动手 = 行为替机制
  验证了吸收，无需任何吸收检查）；星标同样是用户明确动作（优化判别器手动断面，
  [02 §4](02-discriminator.md)，顺产剪切清单）。分类给定后，**时机与范围全是机械扫描**，
  模型零参与。
- **结论句三档**：短 run（≤1–2 对）= **机械摘句**（"问X，答：〈回答结论句/首句规则摘录〉"，
  零 LLM）；长 run = LLM 一句结论（断面内搭车，[02 §4](02-discriminator.md)）；
  验证 run = 判决提取（退出码/测试模式机械；语义验证结论随断面）。
- **run 状态机**：理解/验证消息入账 → 标记可剪积压（答案未交付不能剪）→ 跨 streak 累积 →
  吸收证明到达 → 整串冲刷剪除（surfaceOp replace + 配对平衡 + 影子计价）。
- **验证类处置**：动作到达不直接剪 → 专项判定依赖边（后续动作可能消费验证结果）→
  确认无依赖降级剪除；有依赖或存疑 → 延迟观察窗（后续 K 条消息内指纹/实体零引用才剪）。
  泛化原则：提问/求证凭闭合性可提前剪；其他类型只能观察确认无关（候选标记 + 前向引用窗，
  把对未来的预测变成对过去的观察）。

**标志设计（三道闸，防误解 / 防打回 / 剪得净）**：

1. **带外原则**：run 的判定与范围记在插件状态（卷宗标注），主模型全程看不到任何原始标志
   ——它唯一看得到的是剪后产物（一句结论）。没有可见标志，就没有可误解的东西。
2. **选坐标不造坐标**：模型产出侧唯一契约 = 从枚举好的消息坐标里选 run 边界 + 每段一句结论
   （行式记录，[02 §4](02-discriminator.md) 双通道契约）；解析 = 对枚举表校验，结构上
   几乎不可能打回；失败默认保留。
3. **结论句中立叙述体**：替换物是叙述不是指令——"已吸收：关于 X 的 n 轮问答，结论：…
   （用户已确认理解）" / "已验证：Y 通过，依据：…"——避免后续轮模型把它读成待办或指令。

**误剪反馈**：用户重问被剪内容 = 误剪信号（指纹可检出）→ 阈值修正依据，误判不再静默。

## 4. 剪除落位律（宪法条款）

**上下文是模型的唯一记忆。** 任何剪除的落位内容必须承载依据，三选一：

- **语义在场**：摘要/结论进历史（T-note 结论、run 结论句、机械摘句）；
- **盘上在场**：坐标可机械取回原文（热尾文件读、T0 旧读——写即新真相，盘上是权威）；
- 否则**不许剪**。

纯痕迹 stub 仅限"按定义不影响后续工作"的内容，且已升格为机械摘句（多带几十 token
换依据连续性）。剪除账本带策略版本号（可复现）；`compaction/prune` 影子计价紧随每次剪除。

## 5. 与其余层的分工

- 优化判别器供三分类与剪切清单（run 判定的语义输入）；动作到达的检测本身机械；
- 压缩器（[04](04-compactor.md)）在边界/压力时刻做大额回收，老调用对经 T-boundary 搭车
  ——剪切与压缩共享同一套事务原语（surfaceOp replace + 平衡校验 + 影子计价）；
- 四层防御的单位分配见 [01 §3.5](01-architecture.md)：剪切 = 交换对，边界 = task，
  压力 = 子task，保险丝 = 字节。

## 附录：原生文件工具粒度事实（设计依据，harness 源码核验）

剪切层一切文件类机制的物理边界由原生工具 I/O 粒度决定，登记如下：

| 事实 | 值 | 对设计的影响 |
|---|---|---|
| read 行分页 | offset 1-based，limit ≤ 2000 行（READ_LIMIT），2000 字符/行 | read 事件级剪除面精确（meta 持久化行窗口） |
| read 字节帽 | 50KB（READ_MAX_BYTES）**先于行数生效** | 典型行宽下实际 ~900–1600 行/次 ≈ 10–16K token，一次全价 |
| read meta | `{path, offset, lines[{number,text}], totalLines}` | T0-R 摘抄可保持原生信封格式 |
| edit 结果无行号 | old_string/new_string 唯一匹配；diff 故意丢弃 oldStart，仅 ±3 行上下文 | 写区跨度 = oldText 对读窗单次对齐；补丁链不必要 |
| read-before-edit 强制 | observation policy（FS_NOT_OBSERVED） | 读后写配对结构性保证——T0-R 触发是常态非例外 |
| 五元组 CAS | FS_STALE_VERSION 写前校验 | 成功 edit 的前置读必新鲜，无脏修复 |
| 无快照/撤销 | 文件历史不可回取 | 盘上即唯一真相（写即新真相的物理根据） |
| 双工具栈 | str_replace_editor 无 meta（16K 字符视图） | 文件类机制 v1 仅覆盖 tool-fs 栈；占比由探针统计 |
| grep 溢出落盘 | 250 匹配上限 + grep-results.txt 溢出指针 | 原生"截断 + 落盘指针"先例，剪除产物同构 |
