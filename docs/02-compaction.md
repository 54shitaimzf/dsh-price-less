# 02 · 压缩域：会话历史体积管理

> **⚠️ 状态说明（v0.8.0）**：本域**已落地**部分 = 原生压缩驱动 + 溢出接管（代码：
> `src/task/{orchestrator,driver,range,compaction}.ts`）；其余（摘要区/保留预算/修复识别 + §4.6 搭便车机制——结构化
> 事实抽取/提问式压缩/provenance 置信度 + §4.7 上下文剪切层）为**设计蓝图**（📐，代码未实现）——阅读时以标注为界。
> 域定义：**压缩域管理会话历史（L1）的体积**——在压力/溢出/归档时机执行压缩、摘要与剪枝。
> 本域是体积的**执行侧**：task 边界的判定在输入域（docs/03，判别器），知识沉淀在主插件（docs/12），
> 本域职责：决定历史**什么时候压、压哪些、压完怎么写进账**。

## 0. 它解决什么问题（人话版）

会话历史就像一柜子越堆越满的旧账本——每处理一个任务，旧对话就多一截，直到某次请求时把上下文窗口（contextWindow）塞爆，`CONTEXT_WINDOW_EXCEEDED` 直接把一次本该完成的活拦腰掐断。压缩域（02）就是那个定期"清柜子"的部门：**在不丢掉关键信息的前提下，把历史里的大块冗余压小**，让当前 task 的头尾永远放得下。

它压的是"历史体积"。task 边界的判定由输入域（docs/03）用信号决定，知识沉淀由主插件（docs/12）负责；压缩域的职责是接到"该压了"的信号之后——**什么时候压、压哪些、压完怎么写进账**。

思路是一条主线：**保尾压头，两级保留**。当前 task 的尾部（最新、最有用）按 `retainRatio` 预算逐字留着，头部（旧、可概括）折成摘要；跨 task 的部分收进**摘要区**（只追加、永不改写的历史摘要堆，改写会打断缓存前缀）。凡是文件与寻址域标记为**深度冻结**的内容（**锁定清单**——文件与寻址域冻结的文件块清单，压缩器不许碰），一律不动。

收益与代价都很直白：历史体积被控制在预算内，`compoundedVolume`（历史工具结果被之后每轮反复重读的浪费量）下降；代价是这些摘要必须**字节稳定**（同版本内容逐字节一致——缓存命中的物理基础），否则缓存前缀一断，省下来的又全得还回去。那什么时候关掉/降级？把阈值调小，或关掉 sub1 只保留最低限度的替换——宁可少压，也别压出一个崩掉的缓存前缀。

## 1. 与 dsh-compaction-basic 的关系

- 体积动作（替换历史 span、检查点落盘、配对平衡、缩水校验）**复用既有 `ctx.compaction` 后端**——事务协议（`compaction/start→summary→end`、`shadowedSeqs`、`sourceEventSeqs`）由后端保证；
- 本域提供**决策**：触发时机（压力/溢出）、保留预算与范围、摘要文案与摘要区追加；
- 摘要区（append-only 摘要）由本域直接追加（普通 `user/message` + 带 `sourceEventSeqs` 的溯源），不走替换事务。

> 人话：**"压缩事务"**（替历史做压缩的正式流程：开始→摘要→结束，配对校验由 DSH 既有引擎保证）和"缩水校验"（压缩产物必须比被压区间更小，否则重来）这些低层动作，直接借 DSH 现成的后端来做；本域的职责是**决策**——什么时候压、保留多少、摘要写什么。

## 2. 触发与执行（✅ = 已落地代码，📐 = 蓝图）

| 时机 | 挂点/事件 | 动作 | 状态 |
|---|---|---|---|
| task 结束 | `agent/pre-step`（读投影状态：存在 closed 且未压缩的 task） | 关闭段压 Recent：`selectCompressibleRange` → 原生压缩 → `task-compacted` 信号 | ✅ `task/orchestrator.ts` |
| 溢出 | `agent/request-error`（`CONTEXT_WINDOW_EXCEEDED`） | 兜底 `compaction.compactIfNeeded(..., 'context-overflow')`（auto:false 后接管） | ✅ `task/orchestrator.ts` |
| 压力 | `tokenMeter` ≥ `thresholdRatio`×contextWindow | task 内压缩（保尾压头，两级保留） | 📐 蓝图（`thresholdRatio` 未落地） |
| task 归档 | 消费 `task-boundary` | 旧 task → 摘要区（只追加不可变） | 📐 蓝图（摘要区未落地） |

**task 内压缩（保尾压头 + 预算二级保留）**：

```
当前 task 体积 ≤ 保留预算 → 全部逐字保留
当前 task 体积 >  保留预算 → 两级：
      [task 内头部摘要] + [task 内尾部逐字]
```

- 保留预算 = `retainRatio`(0.16) × contextWindow——以当前 task 尾部为基准；
- 摘要调用复用会话自己的 system + tools + 消息前缀，指令作为最后一条 user 消息追加（docs/06 前缀对齐）；
- 缩水校验：产物 token < 被压区间 token，否则重试；
- 边界切割永不拆散 tool-call/result 配对（复用 `toolPairingBalancedBefore/After`）。

## 3. 逐 task 摘要区（跨 task 归档产物形态）

```
[system + tools]
[task1 摘要] [task2 摘要] [task3 摘要] ……（只追加、不可变）
[当前 task 细致内容]（预算内逐字）
```

1. 只追加、不可变：摘要写入后永不在原位改写（改写会打断缓存前缀）；修正走 L3 差分写入，不回改摘要；
2. 摘要区字节 ≤ `digestBudget`（默认 contextWindow × `digestBudgetRatio`）时不合并；超预算则把最早 N 条并成"阶段摘要"（保留仍真的事实，丢弃过时的）；
3. 固定 schema：每条 = 目的 / 决策 / 产物 / 动过的文件 / 待办；
4. 与 L3 去重：L3 已沉淀的偏好/映射不出现在摘要里（省略或一行指针）；摘要只留"本 task 叙事"。

> **压缩段的有界累积（DSH 设计）**：逐 task 摘要区是**只追加、永不改写**的历史摘要堆——每次 task
> 边界压出的产物**组装成一个压缩段**，追加进这个前缀，**既不参与下一次压缩（已定型，不重喂压缩器），
> 又被组装到上下文的合适位置**（稳定前缀，代表已积累知识）。理论上压缩段本身很小、占用上下文很便宜；
> 但若它**累积过长**，则在下一次压缩时触发**有界滑窗**：**截断最早的任务段、保留最近的几个**（也正是 §3.2
> "超预算把最早 N 条并成阶段摘要"的语义）。这条"累积 + 越界丢最老保最近"是 DSH 域设计；**evalground
> 压缩域实验只实现了前半（压缩段累积、不参与下次压缩、被组装进前缀），截断语义记录于此、暂未实现**——
> 压缩段实际占用、边界行为正是实验要探究的对象。

> 直白讲：**摘要区**就是"只追加、不可改写"的历史摘要堆。它不像普通对话那样可以随时改写，而是**每一段写进去就永远定格**——因为一旦在原位改动，请求开头的**缓存前缀**就变了，后面所有靠它命中的计算全部作废。要修正只能走 L3 差分写入，回改摘要本身是不允许的。超预算时把最早几条并成"阶段摘要"，也就是把过时的细节扔掉、只留下仍然为真的事实。

## 4. 文件与寻址域的协同

- 文件与寻址域提供**锁定清单**（深度冻结的文件块）——压缩器对这些块一律不动；
- 压缩器只在锁定清单之外选候选；优先摘要 read/grep 大块（体积大、信息已由页缓存可重取）；
- 摘要区追加与文件流 vN 递增同守一个字节稳定纪律（docs/06）。

> 这里的配合很简单：文件与寻址域会给你一份"别碰"的清单（**深度冻结**的文件块——删了它后面所有轮次的缓存前缀都会断裂），压缩器就绕开它，只在清单之外挑好压缩的候选，优先挑那些 read/grep 出来又大又能从页缓存重取的大块。两边共用同一条字节稳定纪律。

## 4.5 task 分划压缩驱动器（近因保留尾 × 边界压缩，A3 档）

> **状态（v0.5）**：选择层（`src/task/range-task-partitioned.ts`）+ L0 组件（`digest-schema/cache/store`）
> 已实现并单测；orchestrator 已按 `compressionDriver` 选 `task-partitioned` 接入**近因门选择**（✅）。
> 完整"digest 替换检查点"事务（G2 自研驱动）与缓存/落盘的端到端接线为 📐（见 `Next`）。
> **2026-09-05 范式修正（📐 未实施）**：本档"近因尾**位置保留**"的保留基准被 §4.8 /
> `EXPERIMENT.md §10.6` 的"压缩器申报热尾（任务材料基准）"取代——触发层（何时压）不变，
> 保留层（留什么）换基；实施批次迁移。

**动机**：原生压缩是**纯近因保留**（`selectCompactableRange` 从尾反向累加到 `retainTokens`，只逐字留最近尾，
头部压掉、与任务边界无关）；而"任务一闭合就整段压"会压掉**刚闭合、还很热、正被下一任务引用**的任务。
两者在"近因 vs 边界"上**直接冲突**。本档把它统一为：**近因尾内逐字保留（保热）+ 冷区闭合任务整段压（边界锚定）**。

```
当前 surface
├─ [近因尾]（retainTokens，逐字保留，边界无关——刚闭合任务保热）
└─ [冷区]  ← 仅对"全跨在冷区内 + 未被引用"的闭合任务整段压成 digest
```

- **选择纯函数**（L0，`range-task-partitioned.ts`）：
  - `recencyTailCutoff(nodes, retainTokens)`：近因尾起点（与原生同语义，可对比）；
  - `selectColdClosedTask(state, surfaceNodes, cutoff, {stillReferenced})`：从"闭合+未压缩"中挑
    **最老**的、**全跨冷区**（`lastSurfaceSeq` 下标 < cutoff）且**未被引用**的任务；近因尾内闭合任务**不选**（保热）；
  - `stillReferenced` 为 A4 引用门（深度冻结）——默认关，由调用方注入判据（文件/符号引用，docs/15）。
- **orchestrator 接线**：`compressionDriver='task-partitioned'` 时，在 `agent/pre-step` 用上函数选冷区闭合任务，
  再复用 `selectCompressibleRange`（平衡边界，不切工具调用对）取区间，**事务仍走 harness `compactRegion`**（保真、
  已验证）；近因尾内的闭合任务**逐字保留**（不触发压缩）。
- **摘要 schema**（`digest-schema.ts`）：结构化 digest 显式保留**重发现拦截器**——对象坐标（文件/符号/行区间）、
  精确值/错误串、已尝试&-被拒、待办/归属、逐字权威段。丢失这些正是下游多花一次搜索调用（`extraSearchCalls`）的根源。
- **缓存与按 task 落盘**（L0，`digest-cache.ts` / `digest-store.ts`）：内容寻址缓存（span 哈希，命中即复用，降低
  压缩调用成本）+ `knowledge.json` 的 `taskSummaries.archived[taskId]`（原子写 + 版本 + `source`，跨会话复用不重算）。
- **保守升级 A4**（可选，A3 仍劣化时启用）：更强闭合证据（fail-lazy）+ 引用/深度冻结门 → 只压"真冷却、干净、未被引用"的闭合任务。

## 4.6 压缩产物优化的搭便车机制（📐 设计蓝图）

> **状态（📐）**：以下三个方向均为**设计蓝图**（未实现）。它们共同的技术特征 = **搭便车**：不新增 LLM 调用（那是成本），
> 而是**复用一次必然发生的调用**（判别器在 task 边界判 new_task 时本来就必定读目标用户消息、本来就发 verdict），
> 让它**顺带**产出额外结构化输出。输入成本零（消息已在读），新增成本 = 若干额外输出 token。
> **定位**：属插件**设计空间**；将来压缩功能**定稿设计**时，它们各自作为**单一变量**参与新的实验方案。
> 与 evalground 压缩域测试主轴（压缩是否省 token / 提效 / 不损质量）无关，不进入该测试的臂/消融档。

> §4.6.2 / §4.6.3 仍为设计空间蓝图。

### 4.6.1 结构化事实抽取（搭便车出图谱）——📐 已移入未来路线图

> **状态（2026-09-05 方向修正）**：随**知识图谱整体延后**至未来路线图（docs/00 §12），**当前版本不做**。
> 设计保留如下，供路线图重启时取用。

从"全量对话 → 文本摘要"转向"**结构化事实抽取**"——只抽不可丢的断言（目标/决策/约束/错误/待办/文件坐标），
过程性内容不进压缩器（可重放/可检索）。

- **实现关键 = 搭便车**：判别器（判 new_task）本来就必定读目标用户消息、本来就发 verdict——让它**判边界的同时多输出一个
  图谱 JSON**（实体/动作/依赖）。输入成本零（消息已在读），新增成本 = 几个图谱输出 token。
- **天然对齐**：**每次 task 边界 = 图谱一个节点/一跳**（新任务=新节点、目标+依赖=边），边界判定自带图谱骨架。
- **前提**：① 判别器须 active（observe 不发 verdict 就无这趟调用，得改）；② 图谱"事实性"须校验（边界模型可能幻觉
  不存在的关系——但结构化断言**可校验**，反是优点）；③ 图谱与文本摘要关系要定：**图谱=结构源，摘要应是它的文本投影**
  （单源，不并行生成）。
- 成本：输入零增量；新增极小输出。

### 4.6.2 提问式压缩（搭便车出问题集）

压缩产物不输出叙事总结，而输出"**接手者最可能问的 N 个问题 + 答案**"（我改到哪了？测试过吗？哪个文件？失败原因？）。

- 依据：任务恢复的本质是**填空**；LLM 是概率模型，枚举最可能的后续问题 = 生成对"任务状态空间"的覆盖。信息密度极高。
- **契合机械层（设计优势）**：问题-答案对里的路径/数值/测试结果/失败原因，**每一项天然可机械对照 transcript 验证**
  （grep 该路径是否真出现、测试结果是否真在日志）——叙事摘要难验证（模型可能平滑改写），而问题-答案**可被断言检验**，
  契合 mech 层（确定性事实校验），无需依赖 LLM 判分。
- **落地（再次搭便车）**：判别器在 task 边界顺便生成"接手问题集"——它已判边界、已读这条消息，多输出一列问题即可。
  成本增量≈零。

### 4.6.3 provenance 置信度（机械推导，非模型自报）

- **依据**：LLM 输出"置信度数字"**不是校准概率**，是模型自生成文本，模型并不能知道"我这句话多可信"；
  MoE 稀疏激活（专家路由=离散选择）下更差；**尤其数字与语义混杂时**（token 化拆散数字，模型对数值定位远弱于语义），
  让它在"路径/行号/值+判断"混杂处自报置信度基本不可信。
- **正确做法**：置信度 **不来自模型打分，而来自记录 provenance 的确定性推导**——全是机械可算因子：
  | 因子 | 机械推导方式（确定性，非 LLM） |
  |---|---|
  | 溯源类型 | 源自 `user/message`（逐字权威）/ `tool/result`（真实输出）→ 高；`assistant` 推理 → 低——事件类型已知 |
  | 可重放性 | 能否 `grep log seq` 还原到原始日志？能 → 可验证；不能 → 低（模型平滑产物） |
  | 字段完整度 | 路径+行号+值+待办是否齐全？缺 → 降级——结构检查，机械可算 |
  | 图谱一致性 | 是否与图谱已有断言冲突？冲突 → 标记复核（确定性比较）——**随知识图谱入未来路线图（docs/00 §12），当前版本此因子缺省** |
- **关键转变**：置信度从"模型说这多可信"变为"**这句话在记录里能被验证到什么程度**"——provenance 分级的
  确定性数据结构（每条事实带 `{sourceType, replayable, fieldComplete, consistent}`），全是布尔/枚举，非模型数字。
- **与 4.6.2 耦合**：问题-答案对带 provenance 置信度元数据，接手者对低置信答案会自动重查而非盲信。

**两个剪切器**：

## 4.9 压力压缩路径（📐 设计蓝图，F12 延伸）

> **状态（📐）**：2026-09-05 用户批准定稿，**未实现**。设计级单一事实源 =
> `EXPERIMENT.md §10.7`；本节只挂接域关系。

**定位**：第 3 层（溢出接管）的**语义首段**——`pressureRatio = 0.4` × 模型窗口，
`contextWireTokens`（F10a wire 锚定）触发；hard-truncate 仍为第 4 层保险丝。task 边界
压缩（§4.8）是主劳力且**设计不变**（文件索引 + 直接原文热尾）；压力压缩是**背stop**，
覆盖判别器连续误判 continue（无边界 → 无界增长）等失效模式，失效**独立于判别器**。

- **保留 = 最后一个子任务全量逐字**（无 10K 帽、无申报跨度、无盘上物化）：`cutPoint`
  （缝）由压缩器语义选定——子任务不是预存实体，是压缩器选出的缝；机械仅校验单元存在 +
  工具对平衡。输出 = **进行时检查点**（进度/当前态/下一步，受众 = 当前任务的自己）+ cutPoint。
- **共享机制 A · 未完成边界无总压缩**（与边界压缩器共有）：压力检查点 stub **原样续传、
  绝不重压、不并入 task 级总结构重生**；每次压缩只折上次缝后的增量，输出 = 续传 + 追加——
  摘要 append-only 链（§3 教义延伸到 task 内部，#11 落地）。归档两形态合法：无压力单块 /
  有压力链 [C1][D 边界追加块]。
- **共享机制 B · 热尾下次压缩丢弃**（与边界压缩器共有）：热尾块是缓存非档案，任何后续
  压缩皆折之（坐标锚保留）；热尾申报/物化机制为边界压缩器专属。
- **生产/消费不对称律**：尾部模式是**生产签名**（边界 = 热尾、压力 = 检查点+末段子任务，
  各只生产一种），处理能力**普遍**（任一压缩器处理任一尾部模式——四种触发次序全有定义，
  任意交错闭合）；消费语义为一件共享模块（摘要块→续传，材料块→折叠），验收按四种次序
  组织用例。
- **断路器**：单 task 压力上限 3-4（链长有界）；失败 fail-lazy + 重试一档（离保险丝近，
  重试预算比边界激进）；整面接管与 hard-truncate 为后盾。**实验批次零影响**（task 尺度
  峰值距 400K 远，健康 run 近零开火；AGENTS.md 硬规则措辞修订待批）。
