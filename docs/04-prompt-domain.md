# 04 · 提示词产品域：意图强调与模板产品

> 域定义：**提示词产品域把用户输入优化为"意图强调 + 映射坐标"的执行包**——
> 优化的落点是对**意图的强调**（项目意图 / 框架方向 / 架构设计思路，docs/15 的三级意图树——**唯一意图来源**），
> 以及把意图翻译成**映射坐标**（文件/符号/路径，来自意图映射表）——让模型"找什么、为什么"在一段可见提示词里钉死。
> 产物可审、可改、逐字保留用户原文。知识出口唯一在本域（提示词锚定段，用户可见可改）。

## 0. 它解决什么问题（人话版）

用户给的一句需求往往又短又含糊："把这个报错修一下"——但 agent 真正开工前得先搞清楚**为什么要改、按哪个方向改、去哪改**。缺了这些，它就会到处乱搜、瞎猜方向，白白烧掉一堆轮次和 token。提示词产品域（04）就是那个把用户原话"打包成执行包"的部门：把一句含糊需求，优化成一段**意图强调 + 映射坐标**的可见提示词，让模型"找什么、为什么"在一段话里钉死。

它做的是**对意图的强调**，不是改写你的话。优化 = 包裹 + 加注 + 去重：把你说的路径/数值/约束/合规词句逐字保留（**权威段 / verbatim spans**——原文里的路径/数值/约束/合规词句逐字不动），在其上叠加三级意图（**项目意图/框架方向/架构设计思路**，来自 docs/15 的唯一意图来源树）和**映射坐标**（意图对应的代码位置：文件/符号/行号，agent 直接寻址不用搜索）。

流程是可见、可审、可改的：你在面板点"优化提示词" → host 跑管线出草案 → 预览 diff → 你确认或编辑 → **原地替换**（把对话框里的原文换成优化后的产物）。产物进入**模板缓存**：同类任务下次直接命中（模板在前、实例在后 = 稳定前缀复用），不再重新摸索。

收益是量化的：`firstTurnSuccess` 提升、`intentEmphasisHit` 命中比例上升，且**锚定段有预算**（`anchorBudgetTokens` 默认 2048，超了就裁剪降级）。代价是复杂度与边界：作者要守住"不把用户原文改写掉权威段"的底线；短输入（无贴文无引用）直接**门控**放行、零成本。这份产物一旦进模型就是输入 token、每轮都在付——所以预算必须严守，超了就得降级。

## 1. 交互形态

- 入口：client `conversation.view` 面板"优化提示词"按钮 + `/optimize-prompt` 命令（同一管线）；
- 流程：点击 → host 管线 → 预览 diff → 用户确认/编辑 → 原地替换；
- 产物进入模板缓存：同类型下次直接命中（模板在前、实例在后 = 稳定前缀复用，docs/06）。

> 这里的"产品"感在于：优化的结果不是偷偷塞给模型的一段隐藏指令，而是**用户能看到、能改的一段可见提示词**（提示词产物里的**锚定段**——钉住"为什么做、去哪改"的几段，用户可见可改）。它跟"隐藏层 P"是同一份数据（L3 + 意图映射表）的两个出口，所以永远不许跟 P 漂移。

## 2. 管线

```
草稿输入
 1. 任务类型识别（L0 机械：关键词/模式/模板签名）
 2. 模板命中？ ├─ 命中：模板填充（目标/约束/引用/交付物）——目标槽 = 用户原文（权威段）+ 意图节点投影（docs/15），无 task 级意图
              └─ 未命中：轻包装（只加结构，不改原文）
 3. 意图强调（本域核心）：从意图映射表读取当前 task 关联的意图节点（**唯一意图来源**，docs/15）
     L0 项目意图(为什么) · L1 框架方向(怎么做) · L2 架构设计思路(在哪实现)
     → 写成"意图段"：清晰、简短、恒在前（模型先懂 why 再干活）
     注：task 定义（docs/03）只含边界与证据、不含意图——用户原文目标/风格逐字保留在权威段，意图定义唯一来自 docs/15
 4. 映射坐标：意图 → {file, symbols, lineRange}（映射表检索）→ 指针化
 5. 路径钉死（条件化工具序列，仅本会话工具）+ 方法论摘录（SKILL.md 机械选择）
 6. 逐字保留检查（路径/数值/约束/合规词句 → verbatim spans）
 7. 预览 diff（原文 vs 产物）→ 用户确认/编辑 → 原地替换
```

> 管线一句句翻译：先看**它是哪种任务**（靠机械规则：关键词/模式/模板签名）→ **有没有现成模板**（命中就套模板填槽：目标/约束/引用/交付物；没命中就只加结构、不改原文）→ **强调意图**（从 docs/15 唯一意图来源树里读出跟当前任务相关的意图节点，写成一段"为什么"放在最前面，让模型先懂 why 再干活。注意第 3 步末尾的注释：task 定义不含意图（docs/03）——用户原文里的目标/风格逐字保留在权威段，意图定义唯一来自 docs/15）→ **翻译成映射坐标**（意图 → 文件/符号/行号，供 agent 直接寻址）→ **钉死路径**（条件化工具序列 + 从 SKILL.md 机械摘方法）→ **逐字保留检查**（路径/数值/约束/合规词句 → verbatim spans）→ **预览 diff**（你确认/编辑后再**原地替换**）。

### 2.1 输出格式契约（格式即特征）

```
第一节：Intent（意图段）—— L0/L1/L2 三级意图，固定标题固定措辞，恒为第一段
第二节：Constraints（约束）
第三节：Map（映射坐标：文件/符号/行号 + 路径钉死）
第四节：Deliverable（交付物 + 可并行管道意向）
```

1. **意图恒前置**：模型先看到"为什么"——embedding 分类只需编码该节；
2. 措辞风格固定：同类任务 Intent 节向量聚拢，分类阈值稳定；
3. 格式可复现、可版本化：同版本产物逐字节一致（docs/06）；
4. **锚定段预算**：第三节 + 交付物中的锚定段 ≤ `anchorBudgetTokens`（默认 2048），超限裁剪降级（保留指针、丢弃冗余样本）。

> 这份产物分四节：**Intent（意图段）**——三级意图（L0 项目意图 / L1 框架方向 / L2 架构设计思路），固定标题、固定措辞，永远是第一段；**Constraints（约束）**；**Map（映射坐标）**——文件/符号/行号 + 路径钉死；**Deliverable（交付物 + 可并行管道意向）**。格式就是特征：同类型的任务，其 Intent 节的写法固定得像模板，这样模型一眼就知道是同类，向量也聚拢、分类阈值就稳定。第 4 点里的**锚定段预算**指的是：第三节 + 交付物里属于"锚定段"的部分，总和不能超过 `anchorBudgetTokens`（默认 2048 token），超了就裁掉冗余样本、只留指针。

### 2.2 管道任务模板（编排域采用层联动，docs/13 §7）

- 模板类别"管道任务"：命中条件 = 任务特征含多文件/重构/批量/多个独立修改；
- 命中 → 产物内锚定"管道意向"（调用 `/run-task-pipeline`，goal=意图段，scope=映射坐标文件集），引用式措辞；
- 该意向经预览 → 用户确认 → 才进入产物；度量 `templateEmbedRate`。

> **管道意向**是产物里提示"这条任务可以并行拆分跑"的文字（用户可审）——它只在命中"管道任务"类别时出现，且必须经你预览确认才会写进产物。

## 3. 权威与安全（硬约束的正面表述）

1. 优化 = 包裹 + 加注 + 去重；权威段（verbatim spans）逐字可寻；
2. 路径 = 决策点钉死 + 顺序软化（条件化），保留显式兜底分支；
3. 只引用当前会话装配的工具集；
4. 产物与意图映射表/ L3 同版本；用户编辑产物 → 差异回流（L3 差分 + 映射修正，docs/09 §5）；
5. 门控：短输入（无贴文无引用）直接透传，零成本。

> 这里列的几条是硬约束（不是建议）：**优化只做包裹、加注、去重，绝不改写**；**权威段逐字可寻**；**路径要钉决策点、软化顺序**（条件化，如"若 A 不存在则走 B"），保留显式兜底分支；**只引用当前会话装配的工具集**；产物跟意图映射表/L3 同版本。你编辑产物后，差异会回流成高信号纠正。最后一条**短输入门控**：输入里没贴文、没引用时，直接把原文透传过去、不优化，零成本。

## 4. 模板缓存

| 字段 | 说明 |
|---|---|
| 键 | 任务类型签名（机械识别）+ L3/映射版本号 |
| 值 | 模板主体（字节稳定）+ 实例参数槽（意图段 + 映射坐标） |
| 失效 | L3 版本升 / 映射更新 / 工具集变更 / 模板显式作废 |
| 复用收益 | 同类型请求共享模板块前缀 → 缓存命中（docs/06） |

> **模板缓存**就是"发现任务像以前某类，直接套用模板，不再重新摸索"。它用任务类型签名（机械识别）+ L3/映射版本号作键，值为"字节稳定的模板主体 + 实例参数槽（意图段 + 映射坐标）"。缓存什么时候失效、能省多少，看这张表——关键是前缀复用让同类请求直接命中缓存（docs/06），省掉每次重新生成的开销。

## 5. 用户编辑的反馈回路

- 预览中修改产物 → 差异作为高信号纠正 → L3 差分 + 映射修正（意图唯一来源 docs/15）+ 偏好修正，版本 +1；
- "选择不优化"记为信号（任务类型 + 跳过计数）——供度量统计与实验判定（docs/08），门控参数由人工配置，不做运行时自适应。

> 你在预览里改了产物，这次改动就当成"高信号纠正"回流：L3 差分、映射修正（意图唯一来源 docs/15）、偏好修正，版本 +1。你选择"不优化"，系统也会记一笔（任务类型 + 跳过次数），供度量与实验用——但注意，门控参数是人工配的，**不做运行时自适应**（避免混入运行时改参数的不稳定因素）。

## 6. 事件与度量

- 事件：`anchor/created {taskId, version, bytes, templateId}`（已登记 docs/00 §3）；模板命中与采纳观测走回放（§4/§6），不新增事件；
- `anchorBytes` / `anchorHits`：意图段+映射坐标的字节与同版本复用次数；
- `intentEmphasisHit`：Intent 节命中率（模板缓存命中且意图段被模型采纳的占比）；
- `firstTurnSuccess`、`wastedToolRounds`、`templateHitRate`、`templateEmbedRate`（docs/07）。

## 7. 验收标准

- [ ] verbatim spans 断言：原文权威段逐字存在；
- [ ] 短输入门控：阈值下产物恒等于原文（零改写）；
- [ ] 意图段恒为第一段（格式断言）；
- [ ] 同版本模板+意图段字节一致；用户编辑后 L3 版本确实 +1；
- [ ] 产物内无运行时自适应参数（门控/阈值均为静态配置）。
