## 0. 它解决什么问题（人话版）

把"送进模型的每个 token"当成一次付费打车：多塞一个字就多付一笔，车厢塞得越满，越容易在途中把真正重要的东西挤掉。这套件（`@dsh-external/dsh-context-economy`）要做的，就是让喂给模型的内容**又少又准**——既省 token，任务还跑得更稳。

现在的浪费很具体：一次 `read` 就可能塞进 16K token（实测单次最大 63.5K 字符）；agent 反复 grep 同一个文件、反复重读已经看过的大段结果；历史越滚越大，请求开头的公共前缀（**缓存前缀**）稍微一变，后面全白算。而且这种浪费会"复利（compoundedVolume）"——历史工具结果被之后每一轮反复重读，越往后越贵。

我们的主线只有一条：**把内容分好层，能确定算出来的绝不麻烦模型，能提前钉死的绝不临时搜索，能用版本号复用的绝不重新生成**。关键是"隐藏层 P"（提前拼好的公共前缀包：文件流内容+压缩摘要+任务目标；对象不是文本，不进对话历史）和"可见层提示词产物"（模板 + 锚定段）是**同一份数据的两个出口**——同一个版本源，永远不许漂移。

收益是量化的：压缩域给历史瘦身、输入域（✅ 已落地）用判别器判好 task 边界、提示词域/文件域/编排域（📐 蓝图）把意图钉成坐标、让读文件又省又稳。代价是复杂度：已落地机制都有明确开关（当前真实字段：`sub2IntentMapping`/`taskCompression`/`overflowRecovery`/`compressionDriver`/`discriminator.*`，见 docs/12 §5），每层该不该开、阈值调多少，各域文档逐一交代。

## 6. 公共缓存纪律（字节稳定）

**字节稳定**（同版本内容逐字节一致——缓存命中的物理基础）。三条铁律（完整见 [docs/06](06-cache-prefix.md)）：同输入 → 同输出；稳定在前、动态在后；变更走 delta/版本。
适用对象：模板主体、锚定段（同 task 同版本同字节）、文件流 vN、压缩摘要段、P 组装段。
> 直白讲：**缓存前缀**（请求开头不变的那一段）一旦变化，后面所有靠前缀命中的计算全部失效。所以凡是送进模型的内容，同一种情况必须产出完全一样的字节；要改就改版本，而不是原地改内容。

## 9. 公共宪法与回退链指针

条文与回退链 → [docs/05](05-rule-domain.md)；运行时守卫在主插件（docs/12 §4）。
回退链（**从便宜到贵**，各域共享，不跳层）：用户指令 → 代码分支 → 机械匹配 → 本地 embedding → 极小本地模型 → 主模型最小断面。
> 这条链的意思是：能由**用户可控指令**解决的，绝不写死在代码；能由**代码分支**算出来的，绝不调用模型；能**机械匹配**的，绝不向量化；能**本地向量**的，绝不动大模型。每一级都比下一级又便宜又确定。

## 11. 术语速查（人话版）

给急着翻文档的人一张速查表：每个高频术语只给一句话人话解释（超过 20 字就啰嗦了）。其他文档里第一次出现这些词还会再解释，这里就当总查表用。

| 术语 | 人话解释 |
|---|---|
| **P（公共前缀包）** | 提前拼好的文件流+摘要+目标，放请求最前吃缓存 |
| **锚定段** | 提示词里钉住"为什么做、改哪里"的段，可见可改 |
| **权威段** | 用户原话须逐字保留的部分（路径/数值/约束） |

| **缓存前缀** | 请求开头不变的部分（系统提示/工具表/P/模板主体） |
| **复利（compoundedVolume）** | 历史工具结果被每轮反复重读的浪费量 |
| **回退链** | 从最便宜到最贵的手段序列，不跳层 |
| **降级/退化** | 能力没触发时用更笨但确定的方法兜底 |
| **守卫** | 运行时警察，超标就裁剪、不符就拒绝 |
| **映射坐标** | 意图对应的代码位置（文件/符号/行号），不用搜索 |
| **寻址参考** | 意图映射表（意图→坐标）的定位——隐式知识，只为读文件服务 |

| **页式** | 文件按页读，先给目录页+按需正文页 |

| **差分写** | 只写变化的部分，没变的字节不动 |
| **摘要区** | 压缩域里保留的摘要，替代被归档的旧历史 |
| **管道** | task 内拆子目标并行执行，失败降级回收 |
