# 08 · 对照试验协议（A/B 实验设计）

> 判定"每件插件值多少钱"。方法：**消融阶梯 + 配对复现 + 盲评门控 + 预注册阈值**。
> 规则：只信配对差值（Δ=臂−基线），禁止单次运行结论；先定假设再开跑。

## 0. 它解决什么问题（人话版）

加了这么多省 token 的插件，一个问题立刻摆上台面：**到底哪一件真省钱、值多少钱？** 最容易被自己骗的是——拿一个跑得快的例子当全局结论，或者碰巧这次模型发挥好就归功于机制，模型一升级结论就翻车。所以要有一套实验纪律：**先定标准、再开跑，只信配对差值（Δ=臂−基线），禁止单次运行下结论**。做法是**消融阶梯**（一件一件地开/关，看每件值多少钱）加**配对复现**（同一任务在开关两态各跑一遍，用差值说话——抵消模型升级与环境漂移），再叠一道**盲评门控**（裁判模型看不见臂标签）和**预注册**（开跑前先写下"达到什么标准才算赢"，跑完不许改）。收益是每条结论都有据可依、通得过复查；代价是一次性跑批成本——**11 臂 × 24 任务 × 3 复现 ≈ 792 次会话，每次 1–5 元量级**，这笔钱就是"买结论"的钱。成本能接受就开跑；跑不起就先只留最关心的几项对比。

## 1. 实验臂（消融阶梯）

**消融 = 一件一件地开/关，看每件值多少钱。** A–E 是"从裸机到全开"的台阶，看单件和组合；F–K 是 **leave-one-out**（关掉某一件事，看收益损失多少），回答"少了它差多少"——这组读数比 B/C/D 更可靠；I/J 是管道开关配对，J/K 是自动引入配对。

| 臂 | 配置 | 目标 |
|---|---|---|
| A 基线 | 裸 DSH（默认压缩，无插件） | 基准 |
| B | 只开压缩域 | 体积管理单件收益 |
| C | 只开输入域 | 输入治理单件收益 |
| D | 只开提示词产品域 | 输入优化单件收益 |
| E | 全开 | 组合收益 |
| F* | 全开 − 压缩域 | 压缩域 边际贡献 |
| G* | 全开 − 输入域 | 输入域 边际贡献 |
| H* | 全开 − 提示词产品域 | 提示词产品域 边际贡献 |
| I* | 全开（含编排域） | 管道组合收益（默认关→显式开） |
| J* | 全开 − 编排域 | 编排域边际贡献（即默认基线） |
| K* | 全开 − 自动引入 | 文件与寻址域高置信自动引入的边际贡献（仅关 `fileAutoInject`，docs/15 §2） |

（F–K 为 leave-one-out，回答"少了它差多少"——优先于 B/C/D 读数；I/J 为管道开关配对，J/K 为自动引入配对。）

## 2. 任务集（分层，按工作负载形状 × 可分性）

**任务集 = 实验用的固定任务清单：同一仓库快照、同一工作区、描述落盘。可分性 = 任务能不能被安全拆开并行跑。**

| 层 | 场景 | 可分性 | 任务数 | 假设（H） |
|---|---|---|---|---|
| L1 长多轮（10+ 轮） | 跨天项目任务 | 强耦合 | 3 | 压缩域在腐蚀区降轮次与复利。 |
| L2 文件密集 | 改 bug、重构 | 可分 | 3 | 输入域砍掉查找轮。 |
| L3 高纠正 | 风格/方向反复修改 | 强耦合 | 3 | 提示词产品域 + 偏好修正降返工。 |
| L4 重复类型 | 同类任务 ×5 | 单元 | 3 | 模板复用 + 缓存命中率上升。 |
| L5 短一次性（负对照） | 问一句就走 | 单元 | 3 | 门控零增益、零损伤。 |
| L6 管道判定 | 多文件批量修改（可分）/ 跨文件重构（强耦合）/ 单文件小改（单元） | 三分层 | 3×3 | 可分上层管道无损失且降本；强耦合层不退化；单元层净亏但可由门控兜住。 |

- 固定同一仓库快照、同一工作区；任务 prompt 全部落盘为文件；
- 每任务附**验收标准**（文件改动断言、测试通过、纠正次数）；
- **可分性判定本身是 L0 预检**（文件重叠度/依赖宽度，docs/13 §3），分层即按该判定的实测值归类。

## 3. 判定指标（先过门，再比钱）

顺序很重要：**先过质量门，再谈省钱**——一个便宜但完成率很低的臂不算赢。

- **质量门**：完成率（验收断言）+ 盲评（固定 judge 模型 + 固定 rubric，judge 不见臂标签）+ 人工抽样 10–20%；
- **主指标**：`costPerSuccessfulTask`（见 [docs/07](07-metrics.md)）；
- **机制指标**：`roundsPerTask`、`reDiscoveryTokens`、`compoundedVolume`、并行率、命中率。

## 4. 公平性控制（最易翻车处）

这里是最容易让结论失真的一环，逐条都别省：

1. 同模型、同 provider、同 `reasoning_effort`、同 temperature —— effort 是最大混杂变量；
2. **配对**：同一任务在所有臂各跑一遍；跑序随机化（抵消学习效应）；
3. 复现：每个配置×任务至少跑 3–5 遍，给均值±置信区间（有采样方差）；
4. **交错 + 基线定期重跑**：模型升级/provider 漂移用配对差值自然抵消；
5. **冷/热缓存分开报**：冷（清缓存首跑）与热（连续跑）两列，绝不混合。

## 5. 统计与判定

- 配对差值 Δ = 臂 − 基线；用**不假设正态分布的非参数的配对显著性检验**（Wilcoxon 符号秩检验）+ **自助抽样估计的 95% 置信区间**（bootstrap 95% CI）；报告效应量（如 Δ/CV）；
- **预注册**：开跑前写死假设与阈值，例：
  - H(L2, 输入域)：每任务轮次下降 ≥30% 且质量不降 → 判定"值得保留"；
  - H(L5)：门控层轮次/成本无显著变化（p>0.05 视为无损伤）；
  - H(L6-可分, 编排域)：`firstTurnSuccess` 不降且 `costPerSuccessfulTask` 降 ≥30% → 管道默认开；
  - H(L6-强耦合, 编排域)：质量不降（允许成本持平）→ 门控需显式拦截；质量降 → 门控必须拦（默认关）；
  - H(L6-单元, 编排域)：单任务成本无显著变化 → 管道对单元任务保持关闭。
  - H(L2-文件密集, 自动引入)：注入命中率（`injectedBytesUsed`÷`injectedBytesInjected`）≥70% 且质量不降 → `fileAutoInject` 默认开；命中率 <50% → 保持关闭。
- 阈值调参用**验证集**，最终判定用**测试集**（参数不得回流测试集再调）。

## 6. 运营流程

```text
跑批（每臂×任务 = 全新会话；顺序执行以稳定环境）
  → 收会话日志 → 回放器算指标（docs/07）
  → 质量门（验收 + 盲评）→ 配对统计 → 报告（模板见 docs/07 §6）
```

预算估算：11 臂 × 24 任务 × 3 复现 ≈ 792 次会话；每次 1–5 元量级——这是"买结论"的一次性成本。

## 7. 防自欺清单（跑实验前确认）

- [ ] 便宜但 40% 失败的臂不算赢（质量门先行）；
- [ ] judge 模型与 rubric 跨臂完全一致且盲；
- [ ] 无中途调参（预注册 + 验证/测试集分离）；
- [ ] 冷/热、真实价/固定价全部分开报告。
