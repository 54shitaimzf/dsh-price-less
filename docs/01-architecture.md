# 01 · 架构总纲

> 系统形态、平面与分层、可见性、请求布局、决策链与依赖关系。域细节各归其篇。

## 0. 它解决什么问题（人话版）

机制越加越多，最怕的就是各写各的、互相打架——尤其"模型到底该碰什么、不该碰什么"没有一条准绳，模型就老被拉去干本可以确定性算出来的活，白白烧 token。这篇就是整套架构的"骨架 + 定位说明书"：它告诉你每样东西该待在哪一层、模型看得见什么、一个请求长什么样、一条用户输入走完哪几步。

思路是一条主线：**分好层 + 钉好边界**。先把能力按"实现成本 + 确定性"排成三个平面（L0/L1/L2），再把状态按生命周期分层（L1 会话 / L2 任务 / L3 知识），最后画一条可见性边界——隐藏层（P）与可见层（提示词产物 + 用户原话）各自属于哪边，绝不让看不见的东西偷偷改写模型看见的。

收益是清爽和便宜：目录一清二楚，token 只花在该花的地方；同一份数据的"隐藏出口"（P）与"可见出口"（锚定段）用同一个版本源，永不漂移。代价是得守规矩：少数能偷懒的地方也要按层面走，宁可"笨但确定"，也不让模型去赌。

## 1. 系统形态

```
dsh-context-economy
 └─ 主插件（docs/12）：底座 + 数据面
      恢复编排 · 原生接入 · 内建守卫 · P 服务 · 意图映射表更新(task 周期) · L3 差分写 · 装配
   能力域：
     压缩域    （02）历史体积管理（执行）
     输入域    （03）task 生命周期发现（机械 + 少量 embedding 加权）
     提示词产品域（04）意图强调与模板产品（唯一知识出口，可见）
     编排域    （13）task 内可并行子目标执行方法论（默认关）
     文件与寻址域（15）寻址参考（意图→坐标，写入在主插件；检索供消费）+ 文件治理（页式/快照/补丁链/CAS）
```

> 图里先认几个词：**装配** = 把各域按开关装进主插件；**P** = 提前拼好的"公共前缀包"（文件流内容 + 压缩摘要 + 任务目标，对象不是文本、不进对话历史，进请求时摆最前头吃缓存）；**L3 差分写** = 给最顶层的知识层（偏好/映射/工作摘要）只记变化部分（**差分** = 新增/变更/删除，没变的字节一个都不动）；**CAS** = 比较并交换（Compare-And-Swap，用版本号做写入前校验，不一致就拒绝写入）；**页式/快照/补丁链** = 文件按页读、按版本存快照、变更走补丁；内建**守卫** = 运行时警察（超预算就裁剪、字节不符就拒绝、补丁不规范就拦截、绕过回退链就禁入）。

- 主插件承载横切（唯一性设施）与持久数据面（意图映射表、L3 差分）；
- 能力域承载纵切（各域机制、事件、度量）；
- 依赖方向：能力域 → 主插件接口；编排域 → 压缩/输入/提示词/文件与寻址域产物；其余域无互依。

## 2. 三个平面（实现约束梯度）

| 平面 | 能力 | 成本 | 负责 |
|---|---|---|---|
| L0 确定性 | 分支、查表、字符串/哈希、事件观测 | ≈0 | 纯代码 |
| L1 结构 | 差分标注、模板选择、机械摘录（模型打辅助） | 低 | 代码 + 极小模型 |
| L2 模型最小断面 | 语义核心：工作摘要、偏好语义化、压缩摘要 | 主模型 | 被调用的大模型 |

> 这三个平面就是那句"能确定的绝不麻烦模型"。**L0**（纯代码规则：分支、查表、字符串/哈希、事件观测）零成本；**L1**（轻微结构活：差分标注、模板选择、机械摘录）用极小模型打辅助，成本低；**L2**（真模型干语义活：工作摘要、偏好语义化、压缩摘要）成本最高，只留给"必须拿语义判断"的核心。原则（[规则域](05-rule-domain.md)）：能观测的用日志，能计算的用规则，能查表的用版本；模型只碰语义核心。

## 3. 状态分层

| 层 | 内容 | 生命周期 | 管理 |
|---|---|---|---|
| L1 会话 | 对话历史、工具结果、文件流 vN | 一个 task 的若干轮 | 压缩域（体积）+ 文件与寻址域（页/快照） |
| L2 任务 | task 定义（边界+证据，无意图字段）、已完成/待办、决策点 | task 边界 | 输入域（发现）→ 主插件（归档） |
| L3 知识 | 偏好 / 映射 / 工作摘要（按 task 归档） | 项目 | 主插件（差分写），提示词域（读+编辑写） |
| 意图映射 | 分层意图（项目/框架/架构）↔ 代码实现坐标 | 项目 | 主插件（写入），文件与寻址域（结构） |

> 三层的生命周期一看就懂：**L1 会话** = 一个任务里那几轮对话，最浅；**L2 任务** = 这个任务的定义与进度，随任务边界归档；**L3 知识** = 跨任务的长期记忆（偏好/映射/工作摘要），按 task 归档、跟着项目走；意图映射表是项目级、独立一层。对应关系：task 内压缩管理 L1 体积；task 结束归档 L2 → 差分回写 L3 + 意图映射表更新。

## 4. 可见性

```
隐藏（机制层）
  [system + tools]        ← 系统层
  [P = 文件流段 + 压缩段 + 目标/步骤段]   ← 主插件组装（文件与寻址域/压缩域/输入域贡献段）
可见（会话内容）
  [提示词产物 = 模板 + 锚定段 + 路径]     ← 提示词产品域，用户可审可改
  [用户指令（逐字原文）]                  ← 权威段
```

> 这条边界是全文的重心。**隐藏层**（机制层）里 P 是主插件组装的：文件与寻址域给文件流段、压缩域给压缩段、输入域给目标/步骤段——它不出现给用户看，只默默服务缓存。**可见层**（会话内容）是模型真正看到、用户能审能改的：提示词产物（模板 + **锚定段** + 路径）由提示词产品域生产，用户原话（**权威段**，路径/数值/约束/合规词句必须逐字保留）永远最后一条。隐藏层与可见层共享同一版本源（L3 + 意图映射表）；用户编辑锚定段 → 差分回流（docs/09 §5）；P 是隐藏层资产，锚定是可见层资产——同一数据（意图映射表，唯一意图来源 docs/15）的两个出口，版本一致。

## 5. 请求布局契约

```
[system + tools]  [P]  [模板 + 实例(含锚定段)]  [用户指令]  →  生成
     稳定            稳定     模板稳定/锚定稳定         最后一条
```

> 一条请求按"稳定在前、动态在后"排：头区（system、tools、P、模板主体）越稳越好——**字节稳定**（同版本内容逐字节一致）是缓存命中的物理基础，头区稳定 = 缓存前缀肉盾（docs/06）；P 是顶层缓存锚，目标级更新。锚定段随提示词产物进入历史（可见、可编辑），同 task 同版本同字节；编排域子代理请求 = `P + 拆分片段 i`（docs/13）。

## 6. 决策链（一次用户输入）

```
用户输入
  → 提示词产品域：任务识别(L0) → 模板命中？
      ├─ 命中：意图强调(三级意图段) + 映射坐标(文件/符号/路径) → 预览 → 确认 → 原地替换
      └─ 未命中：透传原文
  → 主模型执行（路径钉死；文件读取走文件与寻址域页式；导航→按需页→快照递增）
  → task 结束（输入域发现）→ 主插件：L3 差分 + 意图映射表更新 + 工作摘要归档 → 压缩域：体积归档
  → 编排域（可选）：task 内可并行子目标 → 管道（共享 P）→ 修改流汇回
```

> 一步步走：先由提示词产品域判断"这是什么任务"（**L0**，纯规则），看能不能套用以前见过的模板（**模板命中** = 发现这次任务跟以前某类长得很像，直接套那个模板）。命中就做**意图强调**（三级意图段）+ 打上**映射坐标**（意图对应的代码位置：文件/符号/路径，agent 不用搜索直接寻址），预览确认后原地替换；没命中就把用户原文透传过去。接着主模型执行——路径钉死（决策点确定、顺序软化），文件读取走文件与寻址域的**页式**（先给目录页，再按需取正文页，快照递增）。task 结束由输入域发现，主插件做 L3 差分 + 意图映射表更新 + 工作摘要归档，压缩域负责体积归档。最后编排域（可选）把 task 里可并行的子目标拆进**管道**（共享 P），修改流再汇回来。

## 8. 验收标准

- [ ] 平面归属清晰：能归 L0/L1 的没有偷渡到 L2；
- [ ] P 与锚定段各自同版本字节一致（哈希断言）；
- [ ] 锚定段 ≤ `anchorBudgetTokens`；
- [ ] 用户指令权威段在任何产物中逐字可寻；
- [ ] 关闭任一能力域，其余功能完整（主插件数据面仍在）。
