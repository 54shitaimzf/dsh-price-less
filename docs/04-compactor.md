## 0. 它解决什么问题（人话版）

剪切层是日常扫地，压缩器是搬家：一个 task 干完了，它那一整段历史（几十 K 的读写、命令、
调试过程）对下一个 task 只剩"结论 + 坐标"价值——继续逐字背着，每轮都在付钱。压缩器在
**正确的时机**（task 闭合 = 那段信息已经稳定，再也不会被改写）把它折叠成小体积档案；
task 内万一长过头（判别器失灵连续误判、用户贴入超大内容），压力路径在 40% 阈值兜底；
再往下还有一道防溢出保险丝。

关键是**什么时候压、压完留什么**：压早了内容还在变（写下的"当前正在做 X"马上被推翻，
摘要比原文更危险——它自带信任）；留错基准（按"时间近因"留最近 10K）会留下一堆正在被
引用的工作材料之外的东西。所以本域的核心决策全部围绕**稳定点**（[01 §3.5](01-architecture.md)）
与**任务材料基准**（§2）。

## 1. 共享事务原语

一切历史变更只走官方通道：`session.append` 带 `surfaceOp:{op:'replace',start,end}` +
完整 `sourceEventSeqs`（被遮蔽节点全列）；压缩事务 = `compaction/start … end` 标记对
（持锁幂等）；`compaction/prune` 影子计价紧随每次遮蔽。**没有旁路**——原生表面 fold
（`deriveMessages()`）因此自动正确派生。跨工具对边界永不拆散
（`toolPairingBalancedBefore/After`）；缩水校验：产物 token < 被压区间 token，否则重试。

## 2. 层 2：边界装配（task 结束压缩 + 热尾原文保留）

**时机根据**（[01 §3.5](01-architecture.md)）：task 闭合 = 区间信息稳定点——对该局部的
读、写、否弃都已完成，事实层此刻冻结才有效；坐标层（文件随后续 task 修改而漂移）由
版本重映射机械吸收，不需要也不允许靠重压修正。

**设计哲学（四条）**：

1. **材料基准替代时序基准**：按"时间近因"保留（位置反向累加留最近 N）在三条价值通道上
   均不占位——不蒸馏理解（原料字节 ≠ 理解）、不省调用（尾部 ≠ 工作集）、不省计费
   （保留 = 继续每轮付钱）。保留的必须是**任务材料**：新 task 开工真正要用的文件与结论。
   非对称原则：进行中任务值得全量材料（≤10K 槽位）；已完成任务只配结论 + 可重放锚。
2. **边界是唯一免费重组窗口**：断裂成本已在边界大 replace 处支付，热尾重装配不新增断裂
   （同一边界事务）。
3. **分工律 = 宪法同构**：模型只做**识别**（从清单抄坐标）与**排序**（重要性降序）；
   harness 独占**计量、裁剪、取真**。模型**零转写**（anti-echo / 字节稳定）且**零算术**
   （自报数字不可信；算术链烧全价思考且常错）。
4. **模型永不被要求知道自己没见过的事**：坐标以"它见过的版本"申报，一切漂移由机械重映射吸收。

**装配流程**：压缩器（输入 = 闭合段全量逐字节——必然调用，热尾申报搭车零调用增量）单次输出
①类型化摘要（type 差异化 schema：plan/impl/verify/wrap 信息块，impl 用坐标指针不嵌代码）
+ ②`hotTail` 范围申报（边界压缩器**专属**）。机械组装：摘要检查点 + 热尾原文
（装配序 = transcript 序，字节稳定）→ 新 task 的 user message 前注入。
渲染面（F5a，2026-09-09）：**结论先行**（wrap→plan→impl→verify）+ 类型标签
（`【结论】/【计划】/【实现】/【验证】`），块序与 schema 校验序（`DIGEST_BLOCK_ORDER`）解耦；产物 schema 不变。

**双通道坐标 + 版本重映射**（"范围 → 原文" = 两级机械查表，模型只生产坐标）：

- **通道 A（文件坐标 → 盘上取真）**：`{path, vN, lineRange?}`——vN 是模型见过的版本；
  快照补丁链按逐版行偏移把区间机械平移 vN→当前版，从**磁盘**取字节（含本会话已落盘编辑
  ——上下文副本是历史快照，改过的文件从上下文取 = 复活旧版本）。文件未改（常态）重映射为
  恒等变换零成本；出界裁剪；已删除丢弃 + 计数。
- **通道 B（历史 span → 账本取真）**：单元 ID 区间——run 输出/stderr 等过程性原文只存在于
  append-only 账本，历史不可变故上下文切片即精确真值。
- **分通道根据**：陈旧只发生在文件（磁盘可变），历史不可变——按可变性分通道是正确性的根。

**预算三环（失败率结构性不升）**：

- 压缩器输入尾部机械追加单元清单（ID·路径·版本对·粗标体量仅供直觉比较）；prompt 明令
  按重要性降序申报、**禁止任何预算计算**；装配器按申报序贪心累加，**到 10K 即停**
  （可少不多，无下限）；单单元超帽 → 尾截断 + 可见标记；tool_call/result 对永不拆分。
- **地板填充**：模型申报装填停机后，若 run 结果类目未被覆盖且预算有余 → 地板补最近验证尾
  （确定性提取：逐字末次验证 ≤3 条 + 逐字失败/错误行 ≤5 条——错误串被转述即失去可搜索性）；
  同单元 ID 去重。
- **三环 fatal 口径不变**（仅解析失败 / schema 违例）：`hotTail` 缺失或坐标全部无效 → 回退
  位置法反向累加 10K（兜底路径）；部分无效 → 丢弃 + 计数；超预算与坏坐标全部机械降级，
  不产生新 fatal。门禁组：**HT 软门**（坐标可解析性机械校验）只降级不拒压。

**热尾生命周期 = 单任务一次性**：装配进新 task 后，热尾字节即该段落的普通成员——任何后续
压缩（压力或边界）皆折之（内容折入检查点/摘要、坐标锚保留，或被新热尾重新申报），
**绝不跨压缩原样滚存**。处置无损 by construction：其源（盘上文件 + append-only 账本）
永久可重推导——**热尾是缓存不是档案**，丢得掉、也敢丢。

## 3. 层 3：压力路径（35% 主模型窗口 · 保尾压头）

**定位**：溢出接管的语义首段——**背stop**，覆盖三种失效模式：单 task 超长生长、判别器
连续误判 continue（无边界 → 边界压缩永不开火 → 无界增长——压力层是判别器失效的保险丝）、
用户贴入超大内容。**失效独立**：压力层绝不引用判别器产物作前提。

**触发**：`pressureRatio = 0.35` × **主模型上下文窗口**（**P20c 用户裁定** 2026-09-09：
一般认为上下文占用超过窗口约 35% 后模型能力开始下降；§5 同步修订）。wire 锚定计量：上次请求精确
token 数 + 回合生成量 + 仅新增消息的校准估计——每步被新 usage 重锚定，不跨步累积。
窗口取主对话模型自身声明的上下文长度（`resolveModelInfo().context.contextWindow`）；
模型未声明窗口时以**假定窗口**（§5）为比例基准，两者都不可用才退回绝对安全网 `thresholdTokens`。
触发间隔天然冷却（压后 ≈ 检查点 + 保留尾，要再涨一大段才会再触）。

**输出 schema（压力模式专属）**：①**进行时检查点**（进度/当前状态/下一步/活约束；
受众 = 当前任务的自己——"我在哪、现在什么为真"，不宣称最终事实）；②`cutPoint` = 最后一个
子任务的起点。子任务不是预存实体，是压缩器选出的**缝**——缝 = 相位边界识别
（[01 §3.5](01-architecture.md)：好缝落在活动类型转换边界），这是它的语义职责；
机械校验仅两条：单元存在 + 缝不切工具对。

**保留区 = [cutPoint..end] 全量逐字**：无 10K 帽、无 span 申报、无盘上物化——保留区本来
就在上下文里，是账本连续尾段。预算控制从"帽"变成"缝的选择"；退化情形（缝靠后、几乎没折出
体积）不断门，靠账本观测迭代。

**两条共享机制（两模式共有）**：

- **机制 A · 未完成边界无总压缩（stub 不可重压律）**：压力检查点 = 未完成边界；摘要字节
  一经写出即不可变；任何后续压缩遇到它**原样续传、绝不重压、绝不并入总结构重生**；
  折叠范围 = 上次缝之后的原始材料；输出 = 续传旧块 + 追加新块。"总"不是单体重写，
  是**追加式链**——归档两形态皆合法：无压力 task = 单块总摘要；有压力 task =
  链 [C1][D 边界追加块]。链长天然有界 = 断路器（单 task 压力上限 3–4，账本可见）；
  保险丝/溢出接管的**紧急折叠可越过断路器**（最后板凳），但仍有硬上限（链长 +3）。
- **机制 B · 热尾下次压缩丢弃**：热尾块是缓存非档案（§2 生命周期）；压力路径把折叠区内的
  热尾折进检查点（坐标锚保留）；热尾申报/物化机制只为边界压缩器服务。

**生产/消费不对称律**：尾部模式是**生产签名**（边界产热尾模式、压力产检查点+末段子任务，
各只生产一种）；处理能力**普遍**（任一压缩器遇到任一尾部模式都有确定语义：摘要块 →
机制 A 续传，材料块 → 机制 B 折叠）。四种触发次序（边→边 / 边→压 / 压→边 / 压→压）
全有定义 → 任意交错闭合，安全性由构造保证。实现推论：尾部识别 + 续传/折叠语义 =
一件共享模块；**验收按四种次序组织用例**（闭合性 = 可测试不变量），不按压缩器组织。

**失败语义**：fatal 口径同 §2；压力折叠失败 fail-lazy 继续全上下文——但离保险丝更近，
重试预算比边界激进一档（失败重试一次再降级）；整面接管与保险丝为后盾。

**经济学**：重复触发时压缩器输入递减（只折增量 + stub 小体积在场）；触发时大前缀已被缓存
→ 折叠调用近缓存价；携带成本只在病态场景支付——不开压力层的替代结局是涨向保险丝。

## 4. 层 4：保险丝（hard-truncate 防溢出安全阀）

- 每次 LLM 请求前估算消息表体积；≥ `contextWindow × truncatePct`（默认 0.8 × 模型真实窗口）
  则重建消息表：保留稳定前缀 `[system, task]` 再补最尾近消息、丢弃最旧历史；
  记 `hard-truncate` 事件与计数器。
- **全臂兜底**（独立于剪切/压缩一切机制），**仅防溢出**：低于地板完全 no-op、不改变任何
  未护栏行为；打分语义不受触发影响，但记录在案供审计。
- **裸模型窗口的使用边界**（**P20c 修订**）：模型真实窗口用于两处——压力阀门比例
  （`pressureRatio` × 窗口，§3/§5）与保险丝地板（`0.8 × 窗口`）；旧「永不作为压缩触发」
  的限制**已由用户裁定解除**（模型能力下降点 = 窗口比例，而非任务峰值尺度）。窗口过大时
  （如 1M）阀门相应后移，风险由断路器 + 保险丝承担；窗口缺失时退回假定窗口/绝对安全网。
  保险丝仍是最后的板凳，不是机制。

## 5. 压缩域窗口标定（硬规则）

- **按主模型窗口比例标定**（**P20c 修订**；旧「按任务尺度标定、不按裸窗口」的教训是 1M 窗
  会让触发门永不过，现由用户裁定以模型能力下降点为准）：压力阀门 = `pressureRatio`（默认 **0.35**）
  × 主模型上下文窗口；模型未声明窗口 → × **假定窗口** `domainTokens`（默认 125K）；
  两者都不可用 → 绝对安全网 `thresholdTokens`（默认 100K）。不变量
  `retain < thresholdTokens` 与 `0 < pressureRatio < 0.8`（config 校验强制，违例整块回退设计值）。
- **估计器必须 wire 校准**：字符/token 常数按 wire 实测校准（`CHARS_PER_TOKEN=1.5`；
  chars/4 会低估 ~2.7×）；wire 锚定 = 精确 usage + 增量估计（§3），每步重锚不累积误差。
- 所有 token 预算（retain/threshold/热尾 10K/检查点）按校准后语义解读；
  保险丝地板独立（§4），两者不可互相当。

## 6. 边界档案（逐 task 归档形态 = 架构经验提取的落点）

```
[system + tools]
[task1 档案] [task2 档案] ……（append-only 压缩段堆：只追加、永不改写）
[当前 task：热尾 + 工作原文]
```

- 每条档案 = 事实层（结论/决策/否弃/待办——稳定点冻结）+ 坐标层（文件/符号/行区间，
  版本重映射吸收漂移）+ 类型化摘要（信息块 schema）；
- **只追加、不可变**：写入后永不在原位改写（改写断缓存前缀）；追加式链归档两形态
  （§3 机制 A）校验都要认；
- **有界硬帽**：档案区硬上限 15K token（绝对设计值，与 retainTokens / thresholdTokens
  同哲学）——超限从最老档案条目起**整条机械截断**直至入限，`archiveTruncate{count,tokens}`
  入账（[07](07-metrics.md) 压缩族）；**不合并、不重压**——合并即二次摘要（§0：摘要自带
  信任，比原文更危险），截断是纯机械边界动作，被截条目仍可从档案快照回溯（[09 §5](09-state.md)）；
- 档案落盘走 [09 §2](09-state.md) 版本协议（原子写 + source + 快照回滚），
  跨会话复用不重算（内容寻址缓存：span 哈希命中即复用）。

## 7. 事件与度量

- 事件（log-only）：随 `compaction/*` 事务；`context-economy/task-digest-created` /
  `task-digest-cache-hit` / `task-deferred{reason}` / `pressure-fired` / `hard-truncate`。
- 度量（定义见 [07](07-metrics.md)）：`compoundedVolume` · `reDiscoveryTokens` ·
  `digestBytes` / `digestEntryCount` · `archiveTruncate{count,tokens}` · `compressionCallCount` / `compressionCacheHitRate` ·
  `extraSearchCalls` · `hotTailTokens` / `hotTailDeclaredUnits` / `hotTailStopReason` /
  `hotTailSource{model|positional-fallback}` / `hotTailFloorFilled` · `pressureFireCount` /

  `hardTruncateCount`。

## 8. 验收标准（协议级断言）

- [ ] 边界/压力/保险丝三路径各有 ≥1 自动化用例；四种触发次序交错闭合（共享模块用例）；
- [ ] 档案区任何一遍回放字节稳定（哈希断言）；追加式链两形态皆可校验；
- [ ] 热尾：模型零转写零算术（输出只含坐标+排序）；贪心停机同输入同装配字节（确定性回归）；
  双通道重映射正确性（补丁链逐版偏移、出界裁剪、删除丢弃）；
- [ ] 压力保留区全量逐字（无帽断言）；检查点 stub 续传字节稳定；断路器生效；
- [ ] 标定：`retain < thresholdTokens` 校验；wire 锚定误差每步重锚（不累积断言）；
- [ ] 保险丝：低于地板 no-op（字节行为不变断言）；触发时前缀保留 + 事件入账；
- [ ] 失败语义：坏坐标/超预算/解析失败全部机械降级，不产生新 fatal（三环回归）。
