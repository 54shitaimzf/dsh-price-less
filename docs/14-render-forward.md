# 14 · 提案：完美转发（原文呈现工具）——可行性评估

> 状态：**📋 评估完成（数据驱动，暂缓立项）**。结论一句话：**不造新工具**——实证显示开发类会话
> 逐字复述占比 ≈0.5%；真正可行的形态是"引用纪律 + 复用既有工具卡片 UI"（零架构成本）。
> 关联：实证账本 `reports/probe-parrot.md`；本页为构想 / 原理 / 场景矩阵 / 若立项的路径 / 度量预注册。

## 0. 构想（人话版）

现象：用户观察到 agent 经常把文档/文件/日志内容**重复呈现**给用户（读过的内容在回复里又打一遍）。
构想：提供一个工具（如 `render_document(range)`），agent 调用后，内容由 **UI 直接渲染成卡片**，
agent 只需输出"引用指令"（几十 token）而不是整段复述（几千 token）——省下输出侧 token。

## 1. 原理（成本模型——何时真能省）

```
现状（复述原文时）:  内容已因 read/工具 进上下文（输入 token 已付）
                    → 模型再把同一字节输出一遍（输出 token 再付一次）   = 同一字节付两次
完美转发:           内容仍进上下文（第一次付费不变）
                    → 模型输出工具调用（几十 token）
                    → client 渲染该内容的原文卡片（UI 免费，不进模型上下文）
                    净省 = 复述量 × 输出单价 − 工具调用开销
```

成立的两个前提：
1. **模型本来要逐字复述已有字节**——此时才是纯浪费，可替换；
2. **用户接受"卡片/可展开"而非文本流**——否则降级回文本，省不成立。

代价核算：输出单价 ≥ 输入单价（DeepSeek 系输出约为输入的 2–6 倍），所以"省输出"方向正确；
但**可替换量 = 逐字复述量**，不是"任何重复呈现"。

## 2. 实证（真实 agent 行为，reports/probe-parrot.md 全文）

2 个独立开发会话（assistant 文本合计 24.4 万字符）：

| 口径 | 逐字复述占比 |
|---|---|
| 复述最近工具结果（narrow） | **0.1%** |
| 复述全会话工具结果（broad） | **0.5%** |
| 复述用户消息原文 | **0.0%** |
| 强转发块（≥3 行原文命中） | 占文本 4.5%，块内逐字命中率仅 2.9% |

**样本形态**：模型"呈现文档"={ 代码/表格行节选（几行，嵌在分析里）+ 重构式摘要（非原文）}，
**几乎不做整段逐字转发**。改写/摘要不是原文 → 无法用"原文渲染"替代。

> 结论：在 DSH 开发类会话，**完美转发可省上限 ≈ 输出 token 的 0.5%**；收益与实现成本
> （client UI + 新块类型（merge-extensible ContentBlockMap）+ 工具 + prompt 纪律 + 降级路径）
> 不成比例。

## 3. 场景矩阵（什么能省、什么不能）

| 场景 | 形态 | 可省？ | 说明 |
|---|---|---|---|
| 用户要求"原样看文件/文档" | 模型贴全文 | ✅ 条件省 | 但这类指令在开发会话稀少（≤1% 消息） |
| 贴报错/日志关键行 | 节选引用嵌分析 | ⚠️ 微量 | 节选总量小（0.5% 内） |
| 讲解/分析中引用代码行 | 几行示例 | ⚠️ 微量 | 同上 |
| 重构式摘要/讲解 | 模型生成文本 | ❌ | 不是原文，渲染卡片会丢改写意图 |
| 模型生成物（代码/JSON/结论） | 模型产物 | ❌ | 工具无法替代生成 |
| assistant 复述自己/系统内容 | 罕见 | ❌ | 本次语料未观测到 |

## 4. 结论与推荐（不立项）

1. **不新增"渲染文档"工具**——收益上限 0.5% 输出 token，不足以覆盖实现与维护成本；
2. **推荐轻量替代（零架构成本，复用现状）**：
   - **引用纪律**（system prompt 规则）：需要原文时，用「见上方 `<tool-result id>` 第 N 段」引用，
     不整段复述；让模型把 read 结果留在既有 tool 卡片里；
   - DSH 的 `ui-tool` 已渲染工具结果卡片（可展开/回看）——prompt 纪律 + 现有 UI 即达成
     "内容不入回复文本"的效果，不需要新块类型/新工具；
   - 若后续想让引用可点击回溯，可在 `conversation.view` slot 做"tool-result 行级定位"（浅 UI 增强），
     仍不涉及新工具面；
3. **何时重新评估**：消费型/展示型会话成为主流量（高频"原样展示"指令）时，复用
   `scripts/probe_parrot.mjs` 复测 parrotRate——用数据说话，不凭感觉。

## 5. 若未来立项的架构路径（备档）

```
新块类型:  ContentBlockMap 增加 { type:'reference', source:'tool-result@seq' | 'file@hash', range }
工具:      render_document(range) → 返回轻量引用描述（几十 token），内容不出模型上下文
client:    conversation.view slot 渲染 reference 块 → 从会话日志/文件按 hash 取原文 → 卡片/可展开/可复制
prompt:    system 规则"原文一律走引用，禁止复述"
降级:      用户要求纯文本/导出 → /render-as-text 命令或卡片复制按钮
```

## 6. 度量预注册（若立项再启用——宪法：先立度量）

- `parrotRate` = assistant 输出中与历史 tool-result/user 原文逐字节重叠的字符占比（`probe_parrot.mjs` 口径，当前基线 0.1–0.5%）；
- `forwardTokenSaved` = 立项后 assistant 输出 token − 基线（配对 Δ，同一会话集）；
- 门：`forwardTokenSaved / 总输出 ≥ 1%` 才值得做（现状 0.5%，需行为纪律先证明可push 到 1%+）。
