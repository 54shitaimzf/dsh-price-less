# 15 · 文件与寻址域：意图寻址参考 + 文件内容进入上下文

> 域定义：**文件与寻址域管"文件内容怎么进上下文"的全部环节——从"该看哪里"（意图 → 坐标的**寻址参考**，
> 隐式知识）到"怎么看进来"（页式/快照/预算，显式机制）。意图的定义、结构、版本、归档唯一在本域
> （**唯一意图来源**）；task 定义（docs/03）只含边界与证据、不含意图；提示词域（docs/04，意图段）、
> 编排域（docs/13，scope）都从本域读意图与坐标；写入侧在主插件（task 周期，docs/12 §7）。
> **知识图表是隐式参考**：它不独立驱动任何动作，全部价值 = 让"该读哪个文件、哪一段"有确定答案。
> 全部为 L0 确定性操作（路径 + hash + 阈值，查表即决）。

## 0. 它解决什么问题（人话版）

读文件是 agent 最常用的动作，也是最容易把上下文撑爆的动作；而读之前还要先知道"该看哪"——找不到位置就得满目录搜。**两个痛点是一根链**："该看哪里"（寻址）决定"怎么看进来"（注入）的上游，注入方式反过来供给寻址的证据。

实测基线（归档会话分析，见 `analysis/`）：DSH 开发会话 30 个文件 / 37 次 read，83% 只读 1 次（均值 1.23 次/文件），可**单次 read 最大 63.5K 字符（≈16K token）**；大型开发会话同一文件最多被全量重读 48 次，73% 的 read 注入来自被多次读取的文件——**全量进历史是浪费 token 和打断缓存前缀的共同源头**。

原设计把这条链拆成两个域（意图映射域 14 管"该看哪"、文件域 15 管"怎么看"）。但盘点映射表的全部消费端——提示词域（意图段 + 锚定指针）、编排域（scope）、读取范围引导——**没有一处显式驱动动作**，全是文件参考。所以合并为一个域：寻址与读取闭环最短——读过的路径/符号直接回流成同一张表的证据（§1.4），坐标更准，读得更省。

机制主体是一串好记的词：**寻址参考**（意图→坐标的表，查表即达，零图算法）；**坐标优先读**（命中坐标直接页式按行区间切，**寻址而非搜索**）；**页式自包含读取**（模型拿到的永远是一页"实际文本"，零描述、零脑补）；**快照 + 补丁链**（v1 → v2 → …，本地缓存、不计输入 token）；**版本戳 CAS**（写前用版本号校验，不一致就拒绝）；**读入即决**（首读按预期用途定形态）；**深度冻结**（文件内容进入历史深处就永远别删——删了缓存前缀断裂，代价 128K 起步）。

收益是量化的：`mappingFindTurns`（寻址效率）、`filePagesPerRead`、`fileBytesInjected`、`fileReReadBytes` 都下降，`fileBytesSavings`（对照全量）上升。代价是复杂度与边界：所有机制都是 L0 确定性操作（路径 + hash + 阈值，查表即决），显式 `read --full` 保留（默认经济，正确性随时可达）。

## 1. 寻址参考（隐式知识：意图 → 坐标）

> 这张表是"隐式参考"——它不自己做任何事，只是回答"这个意图对应哪个文件、哪一段"。**写它、维护它、检索它，都是为了让读文件更准更省**。意图的一切语义都在这张表；task 定义（docs/03）不含意图。

### 1.1 为什么是映射而不是图谱

| 对比 | 意图映射表（本域） | 通用知识图谱 |
|---|---|---|
| 结构 | 三级意图树 + 坐标表 | 节点/边/社区/图算法 |
| 查询 | 逐层命中 → 坐标 | 图遍历/多跳推理 |
| 失效 | 验证坐标存在性（读路径/符号） | 图失效治理 |
| 成本 | 查表,确定性 | 建图/维护/推理 |

规模特征（项目级、几百~几千条、读多写少、查询模式固定）决定：**查表即达，零图算法**。

### 1.2 三级意图树与映射表

```
L0 项目意图:   这个项目做什么 · 产品边界 · 合规底线    → 坐标: 入口模块/README/契约文件
L1 框架方向:   技术栈与生态约定（框架/库/DSH 模式/惯例） → 坐标: 框架接入点/配置/模板
L2 架构设计:   模块职责 · 接口落点 · 关键设计决策       → 坐标: 具体文件/符号/行号

意图节点: { id, layer: L0|L1|L2, 文本, parent?, evidence[], updatedAt }
映射条目: { intentId → 坐标[]:
            { file, symbols?, lineRange?, confidence, evidence, validator } }
```

**三级意图树**由下往上读：**L0 项目意图**——这个项目要做什么、产品边界、合规底线，对应到入口模块/README/契约文件；**L1 框架方向**——技术栈与生态约定（框架/库/DSH 模式/惯例），对应到框架接入点/配置/模板；**L2 架构设计**——模块职责、接口落点、关键设计决策，对应到具体文件/符号/行号。这里 L0/L1/L2 是**从纯代码规则到真模型语义活的三个档位**：L0 纯代码规则、L1 小模型辅助的结构活、L2 真模型语义活。

- 意图节点为**项目级实体**（不挂在 task 上）：task 生命周期内按特征/目标关键词/证据检索**绑定**到映射节点，完成时其证据回流更新映射（§1.4）；知识层的任务级沉淀只有"工作摘要"（docs/09，非意图定义）；
- 分层检索上下文：模型找"为什么"→ L0；找"怎么做"→ L1；找"在哪实现"→ L2——逐层定位。

### 1.3 检索路径（逐层命中，机械优先）

```
查询意图(embedding 或关键词) → 匹配层(精确关键词/路径前缀优先,embedding 补位)
  → 意图节点 + 映射坐标        → 返回 { file, symbols, lineRange }
embedding 端口为空壳(v0.2.0-s6,未接入) → 机械等价(关键词 + 路径前缀 + 符号名表 + Jaccard),无需向量
```

检索是逐层命中、机械优先：先发查询（embedding 或关键词），到匹配层时**精确关键词/路径前缀优先**、embedding 补位，命中意图节点和它的**映射坐标**，返回 `{ file, symbols, lineRange }`。embedding 端口目前是空壳（v0.2.0-s6 未接入，主插件不再携带模型/vendor），故检索走**机械等价物**——关键词 + 路径前缀 + 符号名表 + Jaccard，无需向量；将来接入 `EmbeddingPort` 实现后 embedding 补位生效。

### 1.4 写入（主插件 task 周期执行）

证据优先级（写入时静态定级）：**用户纠正 > 确认的锚定产物 > 工具证据(read/edit/write 路径) > 推断**；
- 新增证据 → 映射增改；置信度 = 证据加权表(固定权重,静态算)；
- L3 差分(偏好/工作摘要)与映射更新同一 task 结束事务提交(docs/12 §7–8)。

写入由主插件在 task 周期做。证据优先级**写入时静态定级**，严格按这条序：**用户纠正 > 确认的锚定产物 > 工具证据（read/edit/write 路径）> 推断**——越靠前越可信。新增证据就增改映射；置信度按**证据加权表**（固定权重）静态算；L3 差分（偏好/工作摘要）与映射更新**同一 task 结束事务提交**（成对提交，要么都成要么都放弃，docs/12 §7–8）。

### 1.5 失效（查询时验证；验证成本与使用点对齐）

**查询时验证**就是用到才验证，不搞周期全量扫描。

| 失效场景 | 验证 | 处置 |
|---|---|---|
| 路径不存在 | 读路径存在性 | `stale` 标记 → 候选路径(近似前缀)匹配 → 重写；无候选 → 移除 |
| 符号不存在 | 文件符号快照比对(懒,查询时) | 同上 |
| 工具不存在 | 当前会话工具集比对 | 边降级为文本指针 |

验证成本与使用点对齐：点查即验证，无周期任务。

## 2. 读取范围契约（寻址引导读取）

1. **坐标优先**：首读路径/范围 = §1 检索命中 `{file, symbols, lineRange}` → 页式按坐标切（导航页 + 指定行区间内容页）；
2. **未命中回退**：映射无命中 → 机械信号（用户显式路径、grep/glob 目标、工具引用统计）→ 仍页式自包含，全量仅 `read --full` 逃生；
3. **证据回流**：命中与未命中的路径/符号/行区间均成为映射证据（§1.4 证据优先级：工具证据 > 推断）——读取行为本身在喂映射表；
4. **范围预算**：多文件坐标集 → 页预算分配（§5），超限按坐标置信度/最新性弃页，弃页记 `file-stream/pruned`。
5. **高置信自动引入（寻址直达，可选）**：映射坐标命中且置信度 ≥ `fileInjectConfidence`（默认 0.8，证据加权分 0–1）→ 该坐标的**行区间内容页在 task 边界/映射更新时一次性卷进 P（文件流段）**，模型首轮即得实际文本，免去 read 导航/内容页轮次（`mappingFindTurns` → 0）；
   - **只进 P**：隐藏层对象，不入会话历史、不进可见层、不替代锚定段（docs/04 §1）；
   - **内容即所得**：注入 = 行区间实际文本（页式自包含），非摘要/描述/导航页（docs/05 §6）；
   - **轮内字节稳定**：决定仅在 task 边界/映射更新时定稿（docs/06 §2 目标级更新），轮内不重算；
   - **未命中/低置信 → 不注入**，走第 1 条坐标优先页式拉取；
   - 开关：`fileAutoInject`（默认 false）——同编排域待遇，注入命中率达标才默认开（docs/08 §5）。

> 这五条就是"先问对地方再读文件"的完整逻辑：①**坐标优先**——首读路径/范围直接取寻址参考（§1）的坐标，按坐标切页（导航页 + 指定行区间内容页），agent 直接寻址、不用搜索；②**未命中回退**——映射没命中就走机械信号（用户显式路径、grep/glob 目标、工具引用统计），仍按页式自包含读，要全量只有 `read --full` 这条逃生通道；③**证据回流**——读到的路径/符号/行区间都回流给映射表当证据（工具证据比推断更可信），读文件本身在喂映射表；④**范围预算**——多个文件时按页预算分配，超了按坐标置信度/最新性弃页，弃页记 `file-stream/pruned`；⑤**高置信自动引入**——命中坐标且够置信就把该行区间内容页**一次性卷进 P（文件流段）**，模型首轮就拿到实际文本，免掉 read 导航/内容页的几轮。注意第 ⑤ 条的四个约束：**只进 P**（隐藏层，不入历史、不进可见层、不替代锚定段）、**内容即所得**（注入的是实际文本，不是摘要/描述/导航页）、**轮内字节稳定**（只在 task 边界/映射更新时定稿，轮内不重算）、**未命中/低置信就不注入**（回去走①页式拉取）。开关 `fileAutoInject` 默认关，命中率达标才默认开。

## 3. 页式自包含读取

| 形态 | 内容 | 体积 |
|---|---|---|
| 导航页（首读默认） | 目录 + 行号索引 + 页表 | ≤ `filePageChars` |
| 内容页（按需） | 指定行区间的实际文本，自包含 | ≤ `filePageChars`（页间 10 行重叠） |

- 模型拿到的永远是**内容即所得**的实际文本，零描述、零脑补；
- 单次返回有界；显式 `read --full` 保留（默认经济，正确性随时可达）；
- 页缓存：`(path, vN, page)` 命中即原字节返回，模型无感知。

> **页式读取**就是把文件切成"目录页 + 内容页"两档：**导航页**（首读默认，给"文件名 + 行号索引"，像书的目录）≤ `filePageChars` 字符；**内容页**（按需，给"指定行区间的实际文本"，自带上下文）也 ≤ `filePageChars`（页间有 10 行重叠防止切裂）。模型拿到的永远是**实际文本**（自包含——模型拿到的就是成品文本，不用再查别的才能用），零描述、零脑补，单次返回有界。要看全量，显式 `read --full`（默认经济，正确性随时可达）。读过的页按 `(path, vN, page)` 缓存，命中就直接返回原文，模型无感知。

> **边界说明（2026-09-05 方向修正）**：按语义选择读取内容（**语义化读取工具**）属**未来路线图**（docs/00 §12），当前版本不做；本域读取契约保持**纯机械**（坐标优先 + 页式 + 快照链），不受影响。

## 4. 快照 + 补丁链 + 唯一性

- 每个读过的文件维护快照链（本地缓存，不计输入 token）：`v1 → v2(apply 补丁后) → …`；
- **唯一性**：同一文件在上下文只保留当前版本（旧版本页不进入管线）；
- 版本戳 = CAS：写前校验，变动即 v+1；编辑后重读走新版本页追加；
- 与编排域共享修改流语言（同 schema 结构化补丁，单线程应用与多线程合流同构）。

> **快照链**就是每个文件在本地留的履历（v1 → v2 → …，磁盘缓存、不计输入 token）：文件改一版，就多一版快照。**唯一性**要求：同一文件在上下文里只保留**当前版本**，旧版本的页不进管线。**版本戳 CAS**（Compare-And-Swap）保证"写前校验写后一致性"：版本号对不上就拒绝——防止两人改到同一处导致内容对不上。编辑后再读走新版本页追加。这套修改流语言跟编排域共用同一 schema（结构化补丁，单线程应用与多线程合流同构）。

## 5. 读入即决 + 深度冻结

模拟结论（`analysis/file-lifecycle-sim2.cjs`：task 20 轮、文件 16K、每轮新增 8K 历史、命中价差 0.9）：

- **决策窗口仅在"深度=0"瞬间**：文件块后面无历史时删除/重建最划算（页式重注 6K vs 驻留 28.8K，4.8 倍优势）；
- **深度 > 0 则永久冻结**：删除导致的后缀历史前缀断裂成本立即 >128K 且单调上升——冷文件也不删；
- 落地为**读入即决**（首读按预期引用（平均 task 规模折算）定模式：引用 ≤1 或可页式 → 导航/页（重建模式）；
  否则全量（追加模式））+ **页预算**（每文件 ≤ `filePageBudget` 页，超限废弃最旧页——被删的是 2K 页，
  断裂成本缩小约 8 倍，删除降为末位工具）。

> 这一节讲"什么时候删文件块、什么时候永远留着"，结论来自一次模拟：**决策窗口只在"深度=0"那一瞬间**——文件块后面还没有任何历史时，删掉/重建最划算（页式重注 6K vs 驻留 28.8K，4.8 倍优势）；**一旦深度 > 0 就永久冻结**——删除它会让后面所有历史的前缀断裂，成本立刻 >128K 且只增不减，所以冷文件也不删。落到产品上就是两招：**读入即决**（首读就按预期引用次数定形态——引用少或可页式就给导航页/页式 = 重建模式；否则给全量 = 追加模式；事后反悔代价大）+ **页预算**（每文件 ≤ `filePageBudget` 页，超了废弃最旧页——被删的只是 2K 的页，断裂成本缩小约 8 倍，删除沦为最后手段）。

## 6. 与各域协同

| 域 | 协同 |
|---|---|
| 主插件 | 映射表写入（task 周期，§1.4）；文件流段贡献进 P；快照恢复入恢复契约（hash 校验） |
| 压缩域 | 提供**锁定清单**（深度冻结块）→ 压缩器不动；提供"页预算超限候选" |
| 提示词域 | 意图段 + 锚定指针（本域数据源）；锚定段引用文件流 vN（版本对齐） |
| 编排域 | scope = 文件集（优先取本域坐标）；修改流同 schema |
| 输入域 | task 按特征检索绑定意图节点；边界证据回流（无意图字段） |
| 守卫 | 坐标残留检测（一致性检查，非业务） |

> 本域跟其他域怎么配合：给主插件**映射表写入**（task 周期执行）与**文件流段进 P**（快照恢复走恢复契约 hash 校验）；给压缩域一张**锁定清单**（深度冻结的文件块，压缩器不许碰）和"页预算超限候选"；给提示词域**意图段与锚定指针**（锚定段再引用**文件流 vN**——文件内容变了就 +1，P 段与锚定段按它对齐）；给编排域提供 scope（文件集，优先取本域坐标）；输入域的 task 绑定意图节点、边界证据回流给映射表；守卫做坐标残留检测。

## 7. 事件与度量

- 事件（log-only，可回放）：
  - 寻址参考：`mapping/updated {intentId, layer, confidence}`、`mapping/stale {intentId, file, reason}`；
  - 读取执行：`file-stream/paged`、`file-stream/snapshotted`、`file-stream/pruned {path, vN, pagesBefore, pagesAfter}`、`file-stream/injected {path, vN, bytes, confidence}`；
- 度量：
  - 寻址：`mappingHit`（命中率）、`mappingFindTurns`（命中后 read 首跳成功轮数——寻址效率）、`mappingStaleRate`（失效比例）；
  - 注入：`filePagesPerRead`、`fileBytesInjected`、`fileReReadBytes`、`fileBytesSavings`（对照全量）、`injectedBytesInjected`/`injectedBytesUsed`（自动引入注入/使用；命中率 = used÷injected，docs/07）。

## 8. 验收标准

- [ ] 三级各自至少一条端到端检索用例（意图 → 坐标 → 锚定段）；
