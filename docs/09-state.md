# 09 · 状态与版本协议

> 域定义：**全部持久状态的单一事实源与版本协议**——卷宗、项目帧、边界档案、优化产物
> 四类实体 + 会话事实（log-only 事件）的可回放重建；恢复契约统编于本文。
> 状态：设计 · 未实现（存储接线见 [11 §4](11-structure.md)）。

## 0. 它解决什么问题（人话版）

机制学到的东西（判别卷宗、项目目标、每个 task 的归档、优化产物）如果不存下来，重启就全丢；
存的地方不唯一、或被两处同时改，就互相打架、版本错乱。所以把全部状态收进一块带版本的
存储：**每类实体自己一个单调版本号，写入必须带来源（source），原子落盘（先写临时文件再
改名——断电不留半截），可回滚（快照）**。另一半是会话事实（发生过什么事）全部记成
log-only 事件——日志 append 后永不重写，状态损毁也能按事件顺序**重放重建**。
核心一句话：**同一版本源永不漂移；盘上算不清的，日志一定能重放出来。**

## 1. 双源结构（durable KV + 会话事实）

| 源 | 载体 | 内容 | 失效语义 |
|---|---|---|---|
| **durable KV** | storageDomain（版本化表，backend 可换 json/sqlite） | 卷宗 / 项目帧 / 边界档案 / 优化产物（加速缓存 + 跨会话复用） | 回退上一版本（快照） |
| **会话事实** | 自定义 **ignorable 事件**进会话 JSONL（append + fsync，committed 永不重写） | `task-boundary` / `judge-*` / `optimize-run` / `shear-applied` / `pressure-fired` / `restore/*`（全 log-only） | **可回放重建**（KV 损毁 = 重放日志重建，KV 只是加速缓存） |

- **可复现双保证**：① 度量账本从会话 JSONL 回放（[07](07-metrics.md)）；
  ② LLM 产物版本寻址，同版本同字节（哈希断言）。
- **workspace 隔离**：按 cwd 分域——项目级实体（项目帧/档案）键含 workspace 标识。

## 2. 实体与版本协议

| 实体 | 内容 | 版本事件 | 写者 |
|---|---|---|---|
| **卷宗 vN** | task 内用户消息原文 + 标注（三分类/回填裁决） | 每条消息追加；星标回填 = vN+1（终审） | 自动断面（追加）/ 星标（回填） |
| **项目帧 vN** | 项目最终目标 + 方面分解 + 技能目录快照 | init 采集 = v1；项目帧修订 / 技能装卸 | init（用户确认）/ 星标 / 目录 watch |
| **边界档案 vN** | 逐 task 归档：事实层 + 坐标层 + 类型化摘要（[04 §6](04-compactor.md)） | task 闭合归档；滑窗合并 | 压缩器（边界事务内） |
| **优化产物 vN** | 星标断面的优化后 prompt（用户确认版） + 行式裁决记录 | 每次星标确认 | 星标通道（用户确认后落盘） |

协议规则（全实体共用）：

1. 各实体**独立版本号**（单实体差分，不整库升版）；`schemaVersion` 全局结构版本；
2. 每次写入必须带 `source`（task ID + 事件类型 + 证据），无来源写入拒绝；
3. **差分写**：只携带增量，不变条目字节不动 → 同版本字节稳定（缓存命中的地基）；
4. 同实体同轮只允许一次提交（进程内互斥）；
5. LLM 产物先版本化落盘再复用（宪法条文三）。

## 3. 读写者矩阵

| 角色 | 卷宗 | 项目帧 | 边界档案 | 优化产物 |
|---|---|---|---|---|
| 优化判别器 | **写**（追加/回填） | 读（稳定前缀） | 读（边界归档触发写） | **写**（用户确认后） |
| 剪切层 | 读（run 标注） | — | — | 读（剪切清单） |
| 压缩器 | 读（边界信号） | — | **写**（边界事务） | — |
| 守卫 | 字节守卫 | 字节守卫 + 引用守卫（技能目录） | 字节守卫 | 引用守卫 + 逐字保留检查 |
| 度量账本 | 只读 | 只读 | 只读 | 只读 |

## 4. 恢复契约

原则：**写进日志/磁盘的才算状态；哪一项坏就只降那一项，其余照常**。

| 状态 | 存哪 | 恢复 | 失效语义 |
|---|---|---|---|
| 卷宗 | durable KV | 读盘 + 版本校验；损毁 → 日志重放 | 当作空卷宗重新积累 |
| 项目帧 | durable KV | 读盘 + 校验 | 退回上一版本；无版本 → 重新 init |
| 边界档案 | durable KV | 读盘 + hash | 回退上一版本 |
| 段状态机（task 表） | 会话日志 fold（纯函数） | 回放重建 | 当作新 task |
| 度量加速缓存 | KV | 重放重算 | 无损（账本在 JSONL） |

恢复序：项目帧 → 卷宗 → 边界档案 → 段状态机 → 度量缓存；每步 `restore/step`，
失败 `restore/degraded`（降级清单），完成 `restore/done`。顺序理由：先救最贵且全局的
（项目帧是判别参照系），再到 task 级（卷宗/档案），最后是无损可重算的（fold/账本）。

## 5. 回滚与审计

- 每次提交保留快照（最近 N=50 版）；回滚 = 恢复快照 + 版本指针回退，
  记 `source: rollback@<version>`；
- 审计接口返回全部提交（version / source / Δ 条数）；
- 任何版本不一致触发 `version-mismatch` 告警事件（log-only）。

## 6. 验收标准

- [ ] 无 source 写入被拒（断言）；并发写不丢版本（互斥 + 原子写）；
- [ ] 同版本各实体哈希一致（CI）；差分写不动不变条目字节；
- [ ] 回放确定：同一段会话 JSONL 重放出同版本卷宗/段状态机/账本（纯函数断言）；
- [ ] 恢复演练：KV 损毁 → 日志回放重建，`restore/degraded` 记账；
- [ ] LLM 产物未落盘不被引用（先版本化再复用断言）。
